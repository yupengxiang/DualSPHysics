# DS-DATA-01 scope override

## Effective scope

This activity builds a broad, reproducible Lagrangian-fluid dataset and a
model-free evaluator. It does not run training, model inference, checkpoint
replay, hyperparameter search, ranking, or model qualification. A dataset
train/validation/test role is metadata for future users; it is not permission
to train a model in this activity.

The activity retains and may reuse existing F3 material, valid CFD outputs,
geometry/control exports, converters, numerical-quality evidence, and failure
records. Existing outputs are read-only unless a new derived artifact is
written with new provenance. A failed family, failed independent tracer, or
unknown model result cannot globally block an otherwise qualified data scope.

## Legacy treatment

The old L1/L2/L2-R learning tasks are recorded as
`superseded_by_owner_scope` in `ACTIVE_TASKS.json`. This is a new activity
record; it does not rewrite old ledgers or completion receipts. Only a process
that is demonstrably part of this activity may be stopped, and no unrelated
user process is to be interrupted. The current snapshot explicitly protects
an unrelated GPU-0 training process and records the pre-existing dataset
coordinators separately.

The old `core-v1` completion receipt is not the DS-DATA-01 completion gate. In
particular, its requirements for formal training runs, material denominators,
three T1 families, and its historical model gates do not apply here. DS-DATA-01
uses per-scope evidence: source provenance, numerical integrity, schema,
independence, split leakage checks, reference quality, and resource receipts.

## Source and baseline

The current worktree is inspected at startup and is not reset or rebased by
this scope change. The historical review baseline is retained as a reference
(`49df6847404b9c2d3d20c465e8f9cf2e00cde712`); the live worktree may be newer.
The full local official package is the D01 source of truth. A package directory
or catalog entry is not counted as reproduced data until an actual case run,
converter audit, and quality receipt exist.

## Continuation policy

Proceed D00 → D01 → D02 → D03 → D04 → D05 → D06 → D07 → D08. At every scope,
run a canary, record the actual mechanism or an evidence-backed negative,
qualify that scope, then start its 4–8-case production batch without waiting
for another family or a model. Preserve all failures and avoid silently
replacing an unsuccessful case with an unrecorded resample.

Independent material tracing is an optional reference layer for a small,
already-qualified subset. Native numerical particle trajectories are the core
product, with shifting, identity, birth/death, exclusion, periodic mapping,
unknown, and censoring semantics stated explicitly.

## Current D00 evidence

`DATASET_STATUS.json` is generated by `scripts/ds_data01_d00_snapshot.py` and
contains the observed commit, branch/remote refs, official-package presence,
legacy assets, process classification, GPU visibility, and queue status. It is
an observation, not a claim that planned cases have been executed.
