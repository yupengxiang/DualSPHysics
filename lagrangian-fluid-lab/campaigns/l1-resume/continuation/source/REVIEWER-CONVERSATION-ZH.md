## 二、Q2并不是“完整官方数值配方”，这一点会直接改变下一步实验

Q1清单记录的官方三维溃坝设置，与实际Q2 XML至少存在以下差异：

| 设置                                    |     官方源配置 |    Q2实际配置 |
| ------------------------------------- | --------: | --------: |
| `StepAlgorithm`                       |     **2** |     **1** |
| `Visco`                               |  **0.01** |  **0.08** |
| `DensityDT`                           |     **3** |     **2** |
| `Boundary / SlipMode / NoPenetration` | 2 / 1 / 0 | 2 / 1 / 0 |

因此，准确的名称应该是：

> **在原L1数值设置上，移植了官方mDBC边界配置的候选桥接。**

它不是“完整官方数值方案已经在本地几何上验证失败”。Q2生成器也明确保留了本地数值策略，并在代码中继续设置 `StepAlgorithm=1`。

**这并不证明哪一个差异导致了底壁异常。**保留旧数值设置、只研究边界实现，本身也是合理实验。需要纠正的是它支持的结论范围。

下一步最有价值的动态候选，是：

**在已经核实合法的同一几何上，使用同版本官方数值策略派生一份完整候选配方。**

这是一项**整体数值方案对照**，不是单因素因果实验。候选成功后可以判断哪条路线值得采用；需要进一步归因时，再做有限的单因素桥接。不应为了形式上“一次只能改一个参数”，长期保留一个尚未证明合适的组合。

## 三、“有底壁异常、没有swept crossing”目前不能被当作独立结论

### 1. 跨墙事件判据存在可复现的漏检

当前 `_segment_face_hits()` 同时要求：

**本段终点已经越过容差带；名义壁面交点又必须位于同一段内。**

这会漏掉“先越过几何面，随后才逐渐超出容差带”的路径。

以底面 `z=0`、容差 `0.0051 m` 为例，我执行的源表达式合成计算得到：

| 同一条直线路径的保存方式                | 当前条件的结果 |
| --------------------------- | ------- |
| `0.002 → -0.006 m`          | 检出跨墙    |
| `0.002 → -0.002 → -0.006 m` | 两段都未检出  |

**只是多保存了一帧，同一次几何跨越就从“检出”变成“未检出”。**所以，Q2报告中的“没有swept crossing”，不能用于反证底壁异常没有真实穿越。

这只是合成检查，**不是断言Q2所有异常都由该缺陷造成**。[检查结果](sandbox:/mnt/data/L1R_Continuation_f104e540/source_expression_results.json) 和可在本地真实模块上执行的探针已附在任务包中。

修复应将三个量分开：

**几何跨面位置区间、超出容差带的异常过程、当前是否位于实体内部。**

旧结果保留，修复后重新读取已有轨迹即可，不需要为审计器修复重新运行CFD。

### 2. 未配置运行域，不等于已经证实没有运行域越界

Q2准备记录中的 `runtime_domain` 为 `null`；当前辅助函数在没有运行域时返回全False。因此，对这一路径而言，零计数首先表示**没有执行显式运行域检查**，不是独立证实没有越界。

应从实际执行配置和运行日志取得求解域，或明确标为 `not_checked/unknown`。这不改变已经记录的原生零排除事实。

### 3. 现有异常规模需要准确理解

Q2最大**瞬时**底壁越界质量为0.032 kg，占初始60.060 kg约 **0.0533%**。这个量不是累计越界质量，也没有说明最大穿透深度或同一批粒子的滞留时间。

它既不能被忽略，也不应该与此前大规模位置排除混为同一个失败。下一步应明确：

> 哪些身份、从哪里、在什么时间越界，进入多深，持续多久，最后在哪里？

这比再报告“198帧存在异常”更能指导修复。
