# R3 G2 F6：Test 14 静水排量/浮力前置诊断

状态：**CPU-only 诊断完成；不构成 Test 14 物理验收。**

机器可读状态：`acceptance_status=diagnostic_only_not_physical_acceptance`，
`scientific_acceptance=not_accepted_physical_validation`。

## 假设与判别

- **H1：** 外壳变换、质量或平衡基准的粗大错误导致 DBC 末段正偏移。若为真，闭合外壳在名义水线处的排水量应明显偏离 `m/rho`，或几何静水平衡应需要很大的 heave。
- **H2：** 被拒的 DBC 路线存在未由几何静水排量解释的有效向上压力/浮力。若为真，已有 DBC 末 1 s 的流体竖向力会接近重力，但记录的刚体状态对应的几何浸没体积会明显更小。
- **H3：** 改用 mDBC 即可解决偏差。本诊断不运行 mDBC；该假设保持未检验，并列为 blocker。

## 可复现方法

脚本读取官方 Test 14 `Float1.STL`，选择最大带符号体积的闭合外表面（3338 个三角形），按既有 R3 路线的毫米制 `X/Y(竖直)/Z` 到世界 `X/Y/Z` 变换。每个表面三角形与低于船体的参考点组成有符号四面体，计算任意水平面以下的排水体积；水平三角面用重复高度公式处理，没有人为抖动。

静水目标是 `m/rho = 0.009750 m³`，水线为 `z=0.800 m`。另外只读取既有六个真实三维 DBC 工况的 `FloatingInfo` CSV 末 1 s，按 `rho*g*V` 将记录流体力换算成“力隐含排水量”。脚本不调用 GenCase、求解器或 GPU；资源策略记录为 GPU indices used `[]`，未来若需要求解器运行仍只能使用物理 GPU 4–7，并遵循 `w00-inventory.json` 的 UUID。

## 结果

| 量 | 结果 |
|---|---:|
| 最大闭合外壳体积 | `0.016931975 m³` |
| 名义水线排水量 | `0.009662575 m³` |
| `m/rho` 目标 | `0.009750000 m³` |
| 名义排水量相对误差 | `-0.897%` |
| 由几何排量预测的平衡 heave | `-0.001238 m`（约 `-1.2 mm`） |
| 几何名义浮力 | `94.790 N`；体重 `95.648 N` |

因此 H1 没有得到支持：外壳/质量模型在名义水线附近是自洽的，无法解释已有报告中的 `+70–120 mm` 末段正偏移。

六个已有 DBC 尾段均满足记录流体竖向力在体重 ±1 N 内，但该刚体中心对应的几何静水浮力只有约 `4.97–46.18 N`；力隐含排水量与几何排水量之比为 `2.07–35.69`。这与 H2 一致，优先提示 DBC 边界压力/有效浮力问题；它不是因果证明，仍可能混入自由面、阻尼区、小域和离散误差。

## 结论与开放 blocker

结论是 **H1 不支持、H2 与已有数据一致但未证实、H3 blocked**。`acceptance_status` 保持诊断-only，不能把 DBC 或 mDBC 宣称为物理通过；此前 `rejected_current_DBC_proxy` 的状态不变。

`open_blockers`：

1. 当前三维 Test 14 DBC proxy 仍被科学拒绝，本诊断不能晋级验收。
2. 为变换后的 Float1 外表面建立并验证完整 mDBC normals/ghost 几何，然后做同两偏移的匹配重跑。
3. 做 DBC-vs-mDBC 静态或静水松弛对照，并分解边界压力/流体力来源。
4. 对 2 m 水池和阻尼区做更大水域敏感性；当前设置只是计算代理。
5. 在 `dp <= 0.02 m` 前不能声称刚体表面分辨率收敛，并需控制释放高度的晶格相位。
6. 在匹配求解器设置中再次确认自由面高度、外壳排水语义、质量与质心约定。
