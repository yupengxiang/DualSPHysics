# L1 GPU 资源策略补充

日期：2026-09-09

用户明确补充：未来两到三天 GPU 会长期被占用；L1 仍可使用允许范围内的 GPU，前提是不会把外部任务挤到显存 OOM。

本补充只修改资源调度方式，不扩大研究范围，也不改变 GPU 4--7 允许列表、GPU 0--3 保护边界、N4 封存状态、solver attempt 上限或 F6=0 决策。L1 执行器因此采用以下可审计约束：

- 每次启动前重新读取物理 GPU index、UUID、已用/总/空闲显存和利用率；
- 只接受 W0 allowlist 中的 GPU 4--7；
- 启动时至少保留 8192 MiB 空闲显存，作为外部任务波动和新 solver 工作集的安全余量；运行中每秒复核，低于 6144 MiB 就终止 L1 solver 并发布为失败 attempt；
- L1 solver 同一时间只启动一个，以避免多个新进程叠加显存需求；
- 记录声明 GPU 与实际启动 GPU；若声明卡没有余量，可选择当前余量最大的 allowlisted 卡；
- 不终止、暂停或重配置外部任务；若没有满足余量门的卡，则本次启动被阻塞并保留 preflight 证据。

这不是“GPU 空闲”的事实声明；每个实际 attempt 的 `gpu_at_launch` 和对应 preflight 才是资源证据。显存阈值是保守的执行安全门，不是物理结果验收门。
