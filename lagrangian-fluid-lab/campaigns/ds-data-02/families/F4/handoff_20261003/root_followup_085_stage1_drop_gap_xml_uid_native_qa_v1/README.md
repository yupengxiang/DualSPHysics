# F4 Root212 XML/UID native initial-QA source package

This package prepares one disabled, Root-owned CPU audit for the eight real
Root195 GenCase outputs. Root195's aggregate receipt remains `failed` with
return code `0`; its eight per-case GenCase receipts, generated XML hashes,
BI4 producer hashes, dimensions, and dynamic counts are bound as independent
inputs. The aggregate is never promoted to completed.

Root196 failed on the adopted source binding, Root210 failed before array
access on an aggregate producer path mismatch, and Root211 failed before a
usable QA result because the BI4 did not expose raw `Mk` and `Type` arrays.
Those receipts and stdout hashes remain preserved evidence. Root212 uses the
successful F4 centered-reference audit contract: the registered CPU worker
reads native `Posd` and `Idp` through the pinned safe decoder, while fluid,
fixed, marker, and UID partitions are derived from each actual generated XML
execution particle block and the observed `Idp` ranges. It says explicitly
that raw native `Mk` and `Type` were not observed; it does not replace them
with constants.

The source worker never opens, hashes, copies, or decodes BI4/VTK/H5/CSV
arrays. On Root's actual CPU run it creates only local symlinks to the
immutable Root195 XML/BI4 and invokes the pinned audit. Future report/index
hashes remain null here. The package does not grant solver, visual,
precision, Q-N, or production status and does not alter any shared registry,
ledger, or Root195 bytes.

Root should review `requests/root212-native-initial-qa.request.json`, run it
with the actual strict CPU worker, and only then feed its completed0
`initial-native-qa-index.json`, binding, and eight case reports into the
fresh084 Root200 binder. A future binder invocation may pass explicit actual
index/binding/receipt paths; no Root211 output is treated as a pass.
