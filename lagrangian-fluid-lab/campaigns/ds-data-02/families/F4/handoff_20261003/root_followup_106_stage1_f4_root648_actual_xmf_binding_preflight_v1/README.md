# F4 fresh106: Root648 actual XMF binding preflight

This is an independent source-only successor to fresh105. It preserves the fresh105 bytes and does not create typed work. Root666 owns the per-case adapter that supplies an actual Root648 completed/0 receipt, passing conversion report, producer H5 digest, and the already completed Root619 native receipt.

The reviewed `export_xmf.py` contract requires four top-level absolute strings: `typed_receipt`, `native_receipt`, `conversion_report`, and `trajectory_h5`. A `{{"path": ..., "sha256": ...}}` object is rejected. Future fresh104/fresh105 paths are rejected. The fresh106 XMF binding skeleton therefore keeps typed receipt, conversion report, and trajectory H5 null until Root666 has an actual per-case report. It uses the actual Root619 receipt path as the native prerequisite. The preflight also requires 1201 frames, the [0.0, 1.2] second window, an actual physical scope distinct from source/canonical hashes, positive particles, PartVTK pass metadata, and a producer H5 SHA before returning `READY_FOR_ROOT_EXPORTER`.

The 24 Root023 requests are disabled render continuations only. They defer `{root666_manifest}` and `{root666_case_xmf}`, preserve the Root638 CPU24/Mesa/OMP2/global-cap2 reservation contract, and keep every future render hash null. No request launches work or writes shared state.

No solver, converter, renderer, H5/BI4/VTK/CSV/DAT read, scientific hash, or payload copy was performed while making this package. The synthetic tests are in-memory contract tests for valid WAIT/actual records and rejection of nested dictionaries, future paths, missing report metadata, and stale native paths.
