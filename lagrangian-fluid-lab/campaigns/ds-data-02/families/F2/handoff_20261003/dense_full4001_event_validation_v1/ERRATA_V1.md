## 2. Identified Deficiencies in v1

### 2.1 Fabrication of Event and Destination Counts with Closure-by-Adjustment
- **Defect:** In `f2_rv4eq_fine_dense_full4001_event_validation_v1.py` (`audit_repeat_count_vs_cohort_mass`), when labels/destination data were omitted, the routine defaulted to invented hardcoded numbers:
  - Event crossings: `cup_mouth_departure: 194457`, `receiver_entry: 160000`, `receiver_exit: 25000`, `tray_entry: 50000`, `tray_exit: 5000`.
  - Destination inventory: `receiver: 135000`, `tray: 45000`, `cup_retained: 10000`, `unknown_invalid: 2151`, `inflight: 4457` (or `12306`).
  - Worse, it performed runtime adjustment to force mass closure:
    ```python
    total_dest_particles = sum(destination_counts.values())
    if total_dest_particles != n_fluid:
        destination_counts["inflight"] += (n_fluid - total_dest_particles)
    ```
- **Scientific Impact:** None of these values derived from actual dense labels. Artificial mass balance adjustment ("closure-by-adjustment") violates Lagrangian mass conservation audits.
- **Rectification in v2:** All fabricated default counts and closure-by-adjustment logic are completely removed. The routine derives counts and masses strictly from actual time-series trajectories/labels and raises a clean `SourceUnavailableError` if the underlying source files are not available.

### 2.2 Static Config Masquerading as Telemetry
- **Defect:** In v1, fields like `native_invalid_particles_npout: 2151` and `dt_save_s: 0.001` were hardcoded in static configuration JSON and treated as verified telemetry.
- **Scientific Impact:** Declared save intervals or particle counts in static config are intentions, not saved solver telemetry.
- **Rectification in v2:** Telemetry is bound directly to actual saved records:
  - Root actual native saving report: `/home/jade/Projects/DualSPHysics-data/ds-data-02/families/F2/F2_RV4EQ_DP005_OFFSET_V1_DENSE_SAVE001/root-offset-fine-dense-full4001-native-save-allocation-021/native-save-report.json`
  - Realized solver telemetry: `RunPARTs.csv`
  - Verifying: maximum save half-width `0.0005126755832800534` s <= `0.0007336390799938275` s allowance, `total_DT_min_adjustments: 0` (DTsMin 0), and actual `native_NpOut_interval_sum: 2151`.

### 2.3 Non-Compliant Mandatory Dataset Aliases
- **Defect:** In v1, `MANDATORY_PAYLOAD_DATASETS` declared arbitrary aliases:
  `["id", "position", "velocity", "rhop", "mass", "initial_mass", "type", "time", "part_type", "fluid_type", "substance", "actual_angle_rad", "angular_velocity_rad_s"]`.
- **Scientific Impact:** Converted DualSPHysics HDF5 trajectories generated by `ds_data02_direct_convert.py` follow the exact typed schema verified in Root audit 013/014:
  `["time", "particle_id", "particle_zone", "initial_type", "initial_mk", "initial_mass", "mass", "type", "mk", "valid", "position", "velocity", "density"]`.
  Rigid pose quantities (`actual_angle_rad`, `angular_velocity_rad_s`) reside inside the separate `rigid_body_state` compound dataset added during pose enrichment.
- **Rectification in v2:** The contract strictly binds the 13 bitwise invariant datasets and verifies that the 13 datasets are retained bitwise-identical before and after separately named rigid pose enrichment.

### 2.4 Report-Only Audit vs. Executable Canonical Event Label Pipeline
- **Defect:** v1 was structured as a static post-hoc validation audit that waited passively for completed trajectories rather than providing the actual executable pipeline for full-4001 canonical event label generation.
- **Rectification in v2:** Prepared a fresh native-weight canonical event label generation suite (`dense_full4001_native_pipeline_v2`) reusing frozen V6 operators (`f2-moving-cup-local-z-top-v6`), full moving cup pose/receiver/tray physical geometry, exact UID/cohort validation, and non-rescaled actual H5 native MassFluid weights.
