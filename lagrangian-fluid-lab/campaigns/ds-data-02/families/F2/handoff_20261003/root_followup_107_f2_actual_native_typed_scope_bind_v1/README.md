# F2 fresh107: actual Root420/421 native to disabled typed bindings

Fresh107 is a source-only metadata handoff for the sixteen F2 cases. Root421
completed all sixteen full401 native runs with OS return code 0; this package
binds those immutable receipt JSON files, Root417 QA/Root419 semantic evidence,
prepared XML/report metadata, and the tested conversion command into disabled
Root-owned NVMe requests. It does not restart native, run conversion, call
`runtime_v2.validate_request`, open/hash BI4, DAT, CSV, H5, VTK, Run.out, or
solver data, or write shared registry/ledger state. Native frame completeness
remains unclaimed until a downstream typed/report audit.

The converter scope probe uses the integration LAB venv to call only
`ds_data02_direct_convert._physical_condition_scope(owner)` and
`canonical_hash(scope)`. It records the actual `legacy-owner-scope.v0` hash as a
prospective scope. The source-plan hash, whole-owner hash, legacy scope, and
canonical physical binding remain separate; `actual_converter_physical_condition_sha256`
and `canonical_physical_binding_sha256` stay null and no canonical/Q-N or
production grant is made.

Each typed request is disabled, Root-owned, CPU2, and constrained to the
existing NVMe cap2, 24 GiB staging peak, 100 GiB NVMe floor, and 500 GiB Home
floor. It preserves the actual 3D counts 418104 total / 21114 fluid / 372840
fixed / 24150 moving / 0 floating, native recipe 4 s / 0.01 s / 401 frames,
strict dispatch SHA, approved decoder/PartVTK input records, and Root230 lease
policy. Future typed receipt, conversion report, and H5 hashes are null.

The sixteen CSV reuse requests are metadata-only and do not rerun PartVTK. They
carry the CSV path/SHA producer record from each completed Root417 QA report.
Root416 requests remain immutable; their historical missing `PartVTK_linux64`
command-input closure is explicitly reported and is not silently repaired or
reclassified.

Run only the source checks from this package:

```text
python3 build_fresh107.py
python3 workers/fresh107_source_contract_validator.py
```

The authoritative outputs are the manifest, `evidence/fresh107-source-validation.json`,
`evidence/fresh107-validator-run.json`, `evidence/legacy-scope-probe.json`, and
`evidence/csv-reuse-closure.json`. No new qualification, precision, visual, or
production count is asserted.
