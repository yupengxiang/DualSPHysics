# F2 v5 event semantics

`f2_handoff_20261002_event_semantics_v5.py` is an independent observation
operator for the F2 moving cup.  The consumed v1 labels use a local-x mouth
predicate.  v5 uses the actual saved rigid pose and the finite local-z top
opening, with body-frame x/y aperture checks.  Outward crossings are
`cup_top_departure`; inward crossings after a departure are `cup_top_return`.

The physical condition hash remains the owner metadata canonical hash.  The
operator hash in `operator_manifest.json` is separate, and the numerical
recipe hash remains separate again.  Therefore changing this observation
operator cannot silently change the physical case identity.

The operator keeps the initial Type=3 `(Zone,Idp)` cohort fixed.  It classifies
finite cup, receiver, tray, and inflight positions from the actual saved
moving pose.  A tray entry requires a prior v5 top departure.  Native invalid
identities remain unknown.  PartVTKOut Motive/position data are retained as
source evidence and can classify a candidate as open-top/domain, legal-tray,
or closed-wall crossing; an invalid identity is never promoted to physical
spill by the labeler.

Run the already converted six-view audit with:

```text
lagrangian-fluid-lab/.venv/bin/python \
  lagrangian-fluid-lab/campaigns/ds-data-02/families/F2/f2_handoff_20261002_event_semantics_v5.py \
  batch-old-six
```

For a new converted RV4 trajectory, use `observe --trajectory ...
--owner-metadata ... [--exclusion-csv ...]`.  The output and report must use a
new directory.  Existing consumed labels, H5, XML, BI4, motion, and audit
bytes are inputs only.

The four completed RV4 coarse/medium conversion handoffs are generated by
`f2_handoff_20261002_event_semantics_v5_requests.py`.  Each request is
CPU-only, binds the actual solver and GenCase receipts, staged XML/BI4/motion,
the v5 source and operator manifest, and first/middle/last native Part files.
The `v5_label_followup` command in each request is deliberately deferred until
that conversion's receipt and trajectory exist; its output must be a separate
labels attempt directory.  The unfinished fine RV4 attempts are not included.

The actual old-six products and comparison are written below the data root
listed in `operator_manifest.json`.  They are observation evidence only; the
comparison deliberately leaves Q-N and production eligibility pending until
the independent save and integration studies use this same operator.

The old-six source trajectories are legacy `.01 s` saves (401 frames over
approximately 4 s); their first observed event brackets are therefore about
`.005 s`.  The separate RV4 requests use `.001 s` saves.  These cadences and
their evidence must not be conflated.
