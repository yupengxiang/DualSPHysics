# F1 fresh090: first24 to 48 source-only physical expansion

This package adds exactly 24 new F1 physical tuples to the preserved first24 source set.  The candidate set is balanced: twelve eccentric-obstacle ECC cases and twelve asymmetric dual-channel DUAL cases.  Heights remain inside the reviewed source interval (ECC 0.11--0.19 m and DUAL 0.22--0.34 m).  Initial fluid velocities use the already exercised 0.10 and 0.20 m/s endpoints and the explicitly prospective 0.15 m/s interpolation.  The `.15` rows are distinct source conditions, but have no visual, Q-N, precision, or production approval.

The 24 new cases are listed in `metadata/candidate-registry.json`.  The first24 audit is retained in `metadata/existing-first24-audit.json`; retries, aliases, resolution changes, and time-window changes do not increase the physical count.  Every new XML changes the selected fluid drawbox height and declares the official `<initials><velocity mkfluid="0" .../></initials>` entry.  ECC keeps the real 1.6 s / 0.01 s / 161-frame recipe; DUAL keeps the real 4.0 s / 0.01 s / 401-frame recipe.  No forcing, motion, mDBC, or solver-option override is added.

`metadata/converter-physical-scope-preflight.json` is produced by calling the unchanged integration `ds_data02_direct_convert._physical_condition_scope` on all 24 sanitized owners.  The physical binding contains only the allowlisted resolution-independent fields; source-axis and candidate status remain outside that binding.  Canonical physical hashes are separate from the future converter report/H5 legacy scope.  Native counts, saved-frame evidence, typed reports, XMF manifests, and render reports are all null until Root runs the strict pipeline.

Each row has disabled Root-owned requests for genuine GenCase, metadata/official-PartVTK initial QA, full native qualification, native frame0 velocity QA, typed NVMe conversion, corrected N3 XMF, and Root023 full-animation render.  The next executable source entry is the GenCase request for any row under `requests/*.gencase.request.json`; Root must first bind the completed/0 receipt and prepared report before enabling initial QA.  The native solver must use the actual prepared GenCase directory, then frame0 QA must pass before typed conversion.  XMF requests use the corrected Root208 exporter with `shape[1:]` vector dimensions and `{attempt_root}/xdmf`; render requests use automatic all-frame native bounds and `{attempt_root}/render`.

The builder and validators read only JSON/XML/source metadata.  They did not read, copy, hash, or launch BI4/H5/CSV/DAT/VTK payloads or any scientific job, and made no shared registry, ledger, or integration-state change.  All requests are `launch_allowed=false`, `execution_allowed=false`, `production_approval=none`, and `q_n=not_assessed`.
