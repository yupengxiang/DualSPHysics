# Fresh178 first24 dynamic entry catalog

This is an F6-owned, metadata-only handoff. It records the authoritative first24 physical members for F2, F3, and F6 (72 inherited accepted deliveries) and points the root process to each case's own accepted decision, native/QA/typed/XMF/render evidence, published XMF manifest/XML, and published PNG references.

The membership authorities are kept as immutable external references. Each family preserves its own first8 subset and does not replace its actual first24 with a planned list. F6's source authority explicitly remains `actual_first24_subset_current_accepted`, with its final48 still incomplete at the time of this handoff. F3's semantic accepted scope and actual native request scope are recorded separately; the `49e319...` semantic anchor and `86562...` native anchor are roles, not physical values.

The catalog hashes only JSON, XML, XMF, and already published PNG evidence. It does not read or hash H5, BI4, CSV, DAT, VTK, or other scientific payloads. It performs no new visual review, launches no task, changes no shared checkpoint or ledger, and grants no case credit, Q-N, Q-E, or numerical-precision result. Native request fields that are absent in the authoritative role-aware index remain absent.

Run the read-only validator from the F6 worktree:

```text
python3 scripts/validate_fresh178.py
```

The catalog is a metadata entry point only. The external absolute paths and their hashes are the producer evidence; any future execution or visual action remains owned by the root process.
