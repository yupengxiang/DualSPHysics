# Fresh174 F5 final48 primary delivery

This package is written in the assigned F3 isolated worktree and describes the
F5 roster frozen at `ROOT_LIVE_RESUMPTION_CHECKPOINT_254` and the Root1335
full336 index: 28 cases have accepted visual decisions and 20 remain registered
pipeline-readiness rows. It grants no case credit, Q-N, Q-E, or numerical
precision credit.

The F5 membership is copied from Root1293's explicit arrays, preserving
`frozen_first8 ⊂ actual_first24 ⊂ registered_final48`. Accepted-count changes
never redefine those arrays, and physical_case_id is the join key even where a
case_id is reused by a mother scenario.

For each accepted case, the catalog binds only its own accepted decision and
case-local native, typed, XMF, bed, render-report, and published-PNG metadata.
Native canonical, typed legacy, XMF declared canonical/source-H5/source-plan,
and bed SourceDef roles are recorded independently. Field presence and absence
are preserved verbatim; a missing native source-plan or process returncode is
not filled from another role. The four Root1293 historical rows with no atomic
publish receipt remain explicit (`A080`, `A120`, `M085_T080`, `M115_T100`):
their render report/PNG references remain available, while no request JSON is
promoted to a terminal receipt.

The twenty pending rows copy only their own cp254 readiness/current-controller
metadata. They are not visual decisions. Frozen observations containing the
historical 1181 or 1191 render labels are marked as historical snapshots only;
they do not become terminal receipts or visual credit. Mutable live status is
not treated as a completed result.

`build_fresh174.py` reads and hashes JSON metadata and stats XMF/XML/PNG
references. Its receipt resolver accepts execution/render-publish receipt
filenames only and rejects enabled/request JSON. `validate_fresh174.py` checks
the cp254 and Root1293 closures, accepted/pending boundary, case-local report
and manifest identity, role presence/absence, bed references, terminal-receipt
contract, report-output containment, and string/dict PNG references.

Neither script opens or hashes H5, BI4, IBI4, CSV, DAT, VTK, VTU, or PVTU
scientific payloads; neither launches work, modifies shared state, or changes
historical evidence.
