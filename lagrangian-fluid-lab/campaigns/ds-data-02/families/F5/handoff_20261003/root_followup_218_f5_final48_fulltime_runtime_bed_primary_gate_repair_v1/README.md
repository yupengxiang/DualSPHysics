# Fresh218 F5 final48 runtime/bed primary-gate repair

This F5-scoped package is a metadata-only successor to immutable source180
commit `1e82b35a62f60828a64e2030cae11923870ba1ca`.  Source180 remains a
readiness assembly and its three toy false-positive cases remain preserved in
the Root1390 audit reference.  Fresh218 adds the actual execution-receipt,
identity, launch/after input-hash, typed lifecycle, exact 801-frame N×3,
XMF/XML time, bed-frame, role-mask, provenance, and published 34-contact/9-key
gates.

The current Root295/current-index1394 inputs contain 37 accepted F5 members
and 11 registered pending members, so the builder writes `readiness.json`.
It writes `final48.json` only after all 48 fixed Root1293 members are accepted
and every case passes the genuine case-bound full-time chain.  Missing or
unreadable provenance is a readiness failure; a registered request is never a
completed receipt.

Only JSON metadata is read and hashed. XML/XMF is parsed for structure/time
metadata and hashed as metadata; PNGs are stat-only. H5, BI4, IBI4, CSV, DAT,
VTK, and other scientific payloads are never opened, copied, or hashed. No
job, solver, renderer, ledger, shared-state write, qualification, or case
credit is performed.

```bash
python3 -B build_fresh218.py \
  --checkpoint /abs/ROOT_LIVE_RESUMPTION_CHECKPOINT_295.json \
  --current-index /abs/full336-current318-actual-final48-delivery-progress-index.json \
  --membership /abs/F5-ACTUAL_FIRST24-DYNAMIC-DELIVERY.json \
  --legacy-catalog /abs/F5-FINAL48-CURRENT30ACCEPTED18PENDING-ACTUAL801-PRIMARY-BED-DELIVERY.json \
  --source-audit /abs/source180-byte-exact-readonly-current37-assembly-and-final-gate-defect-audit.json \
  --output-dir /abs/new-empty-output-dir
```

Use `python3 -B validate_fresh218.py --package . --output-dir /abs/output`
after the builder. The toy tests are local negative tests for lookalike
receipts, missing N×3/nonfinite time metadata, empty bed reports, exact PNG
inventory, missing refs, and overwrite protection.

The package preserves native canonical, typed legacy, XMF condition/physical
field presence, bed SourceDef, source-plan, historical legacy scope, and
source180 audit roles independently. Zero one-DP/two-DP bins are diagnostic
only; numerical precision, sub-DP containment, Q-N, Q-E, production status,
and case credit remain ungranted.
