# F5 fresh083: C082 layer-orientation correction source pack

Root225 ran the fresh082 C082 definition through the official GenCase binary. The binary finished with code 0 and emitted a generated XML, but the strict wrapper returned code 1 because the source contract expected 40710 fluid particles and the generated XML contained 31658. This package records that failure and a source-level correction candidate; it does not reinterpret the failed attempt as a pass.

The C082 profile is a clockwise XZ polygon (signed area -1) extruded in +y. Its `vdp="0,1,2,3,4"` layers are therefore on the profile's exterior/fluid-facing side for the top run and extend four DP (0.08 m) above the mathematical bed. The unchanged fluid box and clipplane are drawn after the bed. The 9052-fluid deficit is consistent with those layers taking ownership of fluid-grid cells. The piston command is unchanged, but the added layer volume also overlaps the piston footprint near x=-0.04..0 and y=-0.15..0.15, so raster ownership can explain the 4210 moving particles versus B071's 3794. Exact per-cell attribution still requires a later registered native audit.

The proposed minimal correction is the one-line layer-direction change to `vdp="0,-1,-2,-3,-4"`. It preserves the closed profile, y extent, 0.20 m vertical thickness, source marker 40/native Mk50 mapping, clipplane, fluid box, piston, motion, and time recipe. It is only a source candidate: no new GenCase request is enabled here, no expected fluid count is hardcoded, and no solver/typed/XMF/bed audit is enabled. Root must obtain a fresh genuine GenCase receipt/XML before any initial QA or short event. C082 attempt 208 and fresh082 bytes remain untouched.

Official evidence is line-bound in `official-drawextrude-evidence.json`. The relevant examples use negative layers when the boundary is drawn before fluid (`StillWedge`, `FreeDrawMode`) and positive layers when the boundary is drawn after fluid (`FallingWedge2D`), matching the proposed sign correction for C082's order.
