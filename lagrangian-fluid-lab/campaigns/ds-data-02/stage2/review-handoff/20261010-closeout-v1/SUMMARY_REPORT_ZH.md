## 1 目标与审阅边界

长期目标是保留 Stage1 的七族、每族 48 例、共 336 例视觉成果，逐步构建可追溯、可重放、具有任务级科学可信度的拉格朗日流体数据集，支持运动、输运、区域交换、事件预测和流固耦合研究。第二阶段不以新增案例数、脚本数、PASS 数或版本号作为成功指标。

2026 年 10 月 7 日云端审阅接受了视觉阶段的有限成果，同时指出科学数组访问、遗漏、可比初态、时间误差、标签和可迁移产品的缺口。它给出的执行方案是参考证据，不构成新增资源或外发权限。真实用户随后建立了长期执行目标；本次用户要求先收尾、总结、提交推送，再进行云端评估，优先于附件中的持续执行措辞。

本报告区分四种事实：实际完成的父任务与收据；已有科学诊断所支持的有限结论；通过源码或制造数据测试的接口；准备了源码或请求但没有执行的任务。这里的“本地复核”不是来自另一个机构的科学独立复现。SHA 和 CRC 证明字节对应，不证明物理正确。

证据编号 E001–E057 对应 `EVIDENCE_INDEX.json`。该文件将保留的原始绝对路径映射到 ZIP 内路径。原报告不改写；后来的解释和状态放在新 sidecar。本次根进程只复核有界元数据、源码和已记录收据，不重新打开生产 H5、BI4、JSONL 或科学数组。

## 3 实际运行的主要结果与失败

### 3.1 遗漏取证取得了真实进展，但尚不能解释为合法输运

原生排除代码、原始身份和保存帧 typed 掩码已在 117 个规范案例上关联。最后的七个独立批次不依赖旧 ROOT326 质量批次屏障，实证完成了 53 个补充关联；不是把准备好的请求改成完成状态。历史范围的第 118 项是未解决别名，保留 UNKNOWN。

原生原因关联可以回答“哪些原生身份发生排除、与当前 typed 保存状态如何对应”，不能直接回答“是否从合法出口流出、真实去哪了、删除对下游事件有多大误差”。`physical_fate`、`legal_flux`、动力学及 Q-I/Q-N/Q-E 仍是 UNKNOWN。质量分母必须是流体的初始质量，不能以固体混合身份数或最大瞬时缺失数替代累计流体丢失影响。

ROOT313 另完成 17 个实际质量影响诊断，核对 typed 选择的初始逐身份质量及原生排除影响。它没有给缺失粒子补轨迹，也没有授予物理去向信用。ROOT316 四哨点几何支持核对同样是实际诊断，尚不构成连续 owner 或穿透精度验收。（E009、E010）

### 3.2 初态生成已经执行，后续质量闭合仍然卡住

ROOT700–708 的九个 GenCase 父任务全部结束，累计完整 CPU 时间 12.813298 秒，持久产物 398,530,844 字节。它们建立了三组 original/coarse/fine 的实际生成证据，不是新 solver 演化。ROOT709 读取了九份原生头部，完整 CPU 时间 2.879695 秒；原报告九项头信息均 UNKNOWN。

随后查明一个解析器问题：保留的 JBinaryData XML 将标量写在 `v=` 属性中，旧解析器没有读取该属性。已新增复用保留 XML 的解析源码，拟用于 ROOT719；**尚未执行该父任务**。因此旧 ROOT709 UNKNOWN 不追溯改成 PASS。即使解析出了 `MassFluid/MassBound`，那也是每粒子质量字段，不能直接冒充整个案例或连续流体 owner 的质量。（E005、E006、E021）

ROOT710 真正执行了九项初态支持诊断，完整 CPU 时间 9.747698 秒。F2/F5 共六项完成，F3 三项在生产 payload 读取前失败，原因是源 XML 记录缺少路径。精确绑定 F3 源 Def/XML 的修复已提交并准备了 ROOT718 source package，尚未运行。故“六项支持诊断成功、三项失败”是本次终态，不是“九哨点全部通过”。（E007、E020）

连续 owner 的新源码合同给出了 F2-S2 18.876 kg、F3-S1 13.066704 kg、F5-S1 287.736 kg 的源几何推导及控制比较。这份合同尚未做真实父任务执行，具体观测尺度也未闭合，不能替代 actual initial native mass 和全形状生成支持核对。F3 的 staged forcing 与 canonical forcing 仍需正确绑定，不能将候选副本哈希作为实际完整控制信用。（E022、E023、E028）

### 3.3 已识别出真正的科学失败和不可识别问题

F5 官方 clip 源连续 owner 为 287.736 kg，旧离散 sample 为约 254.477983 kg，属于初态质量 hard fail。Y-half 修复的 DP010 差异约 −2.2444%，仍 hard fail；DP005 约 −1.1420%，只达到 marginal，未据此放行 solver。没有质量重缩放，也没有把旧 253.264 kg 当作当前 owner 权威。这是有价值的负结果，但尚无已接受的修复参考。（E024–E027）

F1-S2 确有更密保存、same-CFL 与 half-CFL 的真实有界运行、endpoint 和标量链，不应说完全没有新增 CFD。但 ROOT371 判定：异步时刻的现有成对结果无法识别积分误差与输出误差。报告中的差值是诊断量，不是误差上界，不能用插值或后验阈值让它通过。（E008、E040–E043）

F3-S2 已有 coarse/middle/fine 的真实运行及 836 帧原生/紧凑诊断，fine 的诊断记录了 512 个丢失身份。可比连续初态、no-flux 定义、实际积分误差和观测任务界限仍未闭合。因此，三个结果存在，不意味着已经得到收敛趋势或 Q-N。（E032、E044–E049）

F4 有 common-time/output bracket 和缺失原生行的实际核对；补查字段不等于形成可比较的时间误差结果，异步及缺帧的影响仍需隔离。（E050、E054–E057）

### 3.4 迁移与消费者闭环反复失败，必须承认未交付

ROOT242 的 V11、V13、V14 三次 portable 实际父任务均失败，已关闭完整 CPU 费用、记录外部存储并保留部分副本。V11 是旧 actionable output root 未绑定；V13 的具体错误见原失败闭合记录；V14 打开了被禁止的旧 CURRENT，且分区声明不匹配。三次完整 CPU 时间分别为 9.690656、约 9.235 和 54.899197 秒；保留外部副本合计约 12.6 GB。没有成功 barrier，后续等待不能被视为正在执行。（E015–E017）

后续源码进一步检查了嵌套 manifest、真实参数角色和案例身份，确认旧 row78 操作器不能给 canonical65 贴标签。新 ROOT720 source request 对应 401 帧、405 个原生文件，共 7,377,859,532 字节；源代码/解码器/输入闭包已准备，`run_labels=false`。**ROOT720 没有启动，也没有新 typed、标签或迁移成功收据。**（E018、E019）

启动前仍要补 attempt-owned decoder scratch、峰值和外部 storage accounting，以及根包装器的 4 GiB 内存与完整运行时绑定。现有代码默认 `/tmp/ds02-direct-bi4-*` scratch，不能假定输出估计覆盖该峰值。旧 V14/V15 标签操作器仍属于历史身份，新转换之后需要真正的 canonical65 标签适配链。

V28 family-card 新源码目前固定 ROOT412 的 56 项 proof，不能直接声称已经消费 ROOT434 的 78 项；需要前向适配。旧 V27 卡已实际生成，但其信用仍是有界元数据和诊断，而非科学资格目录。

## 7 为什么实质进展仍然有限

以下是执行者的自我评估，供审阅者检验，不是已经证明的科学结论。

第一，很多真实运行只完成了接口或诊断闭包，没有推动一个具体任务从 UNKNOWN 到有误差界的可用状态。源目录、case identity 和资源约束有必要，但版本化修补、检查点和证明路径变成主要工作量。冻结时有 1,226 份 checkpoint 记录，它们不是 1,226 个独立实验。下一轮应按可验收观测和成品链衡量进展。

第二，身份和嵌套输入问题过晚暴露。portable 多轮运行后仍碰到旧 CURRENT、未绑定目录、row78/canonical65 混用风险。这些问题本应在低成本接口反例中全部暴露，之后才复制 GB 数据。新的规范入口改善了情况，但不能弥补尚未得到的实际成功链。

第三，执行图把独立任务串在旧 portable→support→frame0→mass→native→GenCase 等屏障后，形成不必要的等待。后来用独立 ROOT700–708 和 ROOT711–717 证明部分工作并无科学依赖，但该解耦发生得晚。不能把“仍有 waiter”当作任务正在取得进展。

第四，缺少足够早的物理比较准入。连续几何 owner、离散质量、真实控制和时间戳不闭合时，继续生成更细数据不一定带来可比较参考。F5 质量 hard fail、F1 异步误差不可识别和 F3 排除身份是具体证据；它们需要一个明确的研究设计终态或有限修复，而不是继续修报告接口。

第五，工作面过宽。335 掩码、117 原生关联和七族诊断产物有用，但仍没有先完成一个规范案例的可迁移闭环，或一个哨点的任务级参考资格。这是执行编排与优先级问题，不能只归因于数据难或代理工具限制。

我们不建议在云端审阅前继续增加同类 source 文档、版本或数组复制。需要先判断当前局部产物是否足以独立交付，并删减不能改变科学判断的支线。

## 8 建议云端审阅后选择的下一里程碑

建议把下轮目标压到三个可独立停止、可明确验收的结果，而不是一次恢复整个长任务图；具体选择由审阅者给出。

1. **一个真实可搬迁案例闭环。** 以 canonical65 或审阅者选定的更干净案例，补齐 scratch/预算/身份前置，然后实际 raw→typed→reader/restorer→诊断标签→evaluator→独立路径加载。交付命令、哈希、日志和范围；不把历史 row78 操作器直接复用为新身份标签。该闭环可以先交付 diagnostic，不必等待全族 Q-N。
2. **一个真正科学参考结论。** 从已有真实数据中选最接近准入的哨点；先固定连续 owner、原生初态支持、控制、共同查询时刻和 L/T/v/KE 尺度，再执行最小时间窗比较。可接受终态包括限定任务 Q-N、明确 numerical failure 或证据不足；不能以三个分辨率存在作为验收。F3-S2 可复用已有结果，但必须处理 512 身份排除和 no-flux；F1-S2 必须重设计可分离时间比较；F5 不应在 owner hard fail 时继续 solver。
3. **复用扫描并物化范围目录。** 后续按资源恢复剩余 256 个字段扫描，合并 117 案例遗漏证据，输出 case/task/window 的实际 eligible、censored 和 UNKNOWN。宏观目录应直接消费真实证明，避免每次报告重读数组。这个目录可以作为独立诊断产品，但不能再次替代任务误差研究。

ROOT718/719/721 的三个小型前置父任务可支持第二项，但是否都值得执行、是否选这三哨点，应由审阅决定。ROOT720 当前 1 CPU、3600 秒、输出估计约 1.93 GB 不含已闭合的 scratch 峰值；没有可靠峰值不能承诺放行。候选源码合同不是资源或科学准入授权。

外部 raw 窗口重放是另外一个明确缺口。本次 ZIP 提供元数据与源码审阅证据，**不提供完整科学数组重放能力**。应优先选择每族一个关键事件短窗或更小的首个诊断闭环，按实际字节和许可打包；无对象存储时只保留本地包，不能伪造可下载地址。
