# 并行、数据所有权与持续执行

## 角色
1名总协调/集成；7名family owner；共享运行/数据工程1名；质量/标签/划分1名；独立抽查可作为短期角色。七族研究并行，重求解的并发受实际资源管理而不是代理数量控制。

每个family owner完整负责其案例原始字节→适用观测→哨点矩阵→家族资格→标签/内部包，不能把所有科学判断推给协调者。共享库改动以小补丁由维护者集成；家族分支互相不批量merge重叠历史。

## 进程和GPU
沿用真实所有者允许的GPU集合与UUID。报告中的[2,5,6,7]仅旧runtime偏好，不是新授权；CLI -gpu:0可能是CUDA_VISIBLE_DEVICES中的逻辑0，禁止按其推断物理卡。
默认4个重solver并行；原始/typed/临时存储、GPU/CPU/RAM测量可靠后允许至多7个，每卡1个solver。不得把空闲显存当作外部作业可以被抢占的许可；发现外部进程则不启动，已有任务按保护政策处理，只杀自己进程组。
转换最初2个，I/O/RAM稳定后最多4个。独立material tracer低优先，不阻塞原生数值标签。所有CPU任务申报core/time，不绕过预算。

## 入口与产物
统一strict_dispatch或等价通过集成测试的入口，scope guard绑定自身及实际程序/输入SHA。stdout持续排空或直接文件，不等poll退出才communicate；sidecar receipt有专用文件。并发必须正整数，父进程中断执行各自安全收口。失败日志保留。
不为每次case复制完整历史代码树；记录干净commit与必要文件哈希，脏工作树的执行字节必须另行快照且有实际映射。静态源/几何/控制共享只读，执行目录独立。一个原生CFD invocation、一张attempt记录、一份预约/释放；不要为了剩余分类额度把生产改名资格或反之。

## 状态图
READY -> RUNNING -> EXECUTION_COMPLETE -> AUDIT_COMPLETE -> ACCEPTED_SCOPED / FAILED_KNOWN / UNKNOWN_EVIDENCE。
FAILED_KNOWN触发有限repair/fallback；输入共因错误停受影响的批次，不停全部family；UNKNOWN_EVIDENCE若可从原数据读出，则产生实际读取任务而非外部阻塞。
资格矩阵在本地资源足够、依赖满足时继续，不等待云端review sign-off。只要仍有ready且信息增益明确的授权任务，checkpoint不能令goal终止。任务图中包含新机制探针的条件触发，不将未触发任务谎称已执行。

## 提交与审阅
每个逻辑改动及时commit/push；新科学结果提交精简可引用证据（方法/统计/失效/实际字节指针），原始大数组走获准数据根，不进入普通Git。公共索引单写者事务更新，family产生不可变receipt，通过集成者导入。
中间检查点不要求用户回复。正常每完成一种证据（原始审计、参考矩阵、标签集、家族产品）发简短非阻塞摘要；无工具回写对话不影响本地继续。

## 停止与时限
截止/预算/磁盘下限是真正硬边界；尽早估算完成当前job的余量。无法在剩余期限完成的高开销任务不强启；自动转可完成的分析或打包。
需要额外窗口时主Agent给出一次合并请求：哪些具体case/观测、预计GPU/CPU/存储、增量信息、已用量与新截止，不能制造无限重复审批。
