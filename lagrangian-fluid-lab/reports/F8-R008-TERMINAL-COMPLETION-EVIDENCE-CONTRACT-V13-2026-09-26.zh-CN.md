# F8 R008 Terminal Completion Evidence Contract v13

**Status:** additive proposal only; diagnostic-only; no solver/execution/readiness/qualification authority. Effective contract remains v3 plus v4–v12 and this amendment. V1–V12 and review records remain immutable. No trusted I/O supervisor, broker, ptrace monitor, fanotify dispatcher, or verifier is deployed.

V12 review result: `REVISE`, no P0. The configured Terra High review found that native output-FD calls and broker `pidfd_getfd()` operations lacked one shared lifecycle lock; address-space census/copy-out evidence was not yet an auditable mechanism; fanotify queue ownership and cross-actor event order were underspecified; the syscall table was illustrative rather than exhaustive; and map classes lacked a common raw-row identity. V13 replaces those clauses with one serialized output-I/O state machine, a single fanotify queue owner, an exact pinned syscall-number universe, and a canonical raw maps partition. Reviewer model identity was not attested.

## 1. One serialized output-I/O state machine

Replace V12 §§1–3's separate FD-slot, broker, and native-operation rules with one per-attempt `output_io_arbiter`. No target or broker operation may touch an output pathname, registered output FD, or output open-file description without holding exactly one monotonically sequenced `io_token`. At most one such token is live. It begins before a target syscall is resumed or a broker syscall is dispatched and remains held through syscall completion, result/copy-out capture, broker temporary-FD close, fanotify-response completion, and a loss-free drain of every watched fanotify group to `EAGAIN`. No second output operation can begin before release.

`output_io_arbiter` has exact keys `{schema,attempt_id,supervisor_sha256,ptrace_profile_sha256,broker_profile_sha256,task_census_id,record_count,records_sha256,records}`. Each sorted contiguous record is `{io_token,actor_role,actor_pid,actor_start_ticks,actor_tid,tid_start_ticks,mm_id,files_table_id,target_syscall_sequence,notification_id,broker_transaction_id,broker_syscall_sequences,fd,open_file_description_id,fanotify_event_refs,copyout_ref,exit_result,drain_ids,notification_id_validated_before_effect,notification_id_validated_before_response,operation_complete,lock_released}`. `actor_role` is `writer`, `broker`, or `fanotify_dispatcher`; nullable fields are fixed by that role and operation. A missing syscall stop, operation row, result, drain, event edge, or lock transition makes the whole attempt incomplete/open.

Before guarded execution, the supervisor obtains a host-visible task census bound to PID/TID start times and pidfds. While tasks are stopped, it compares every visible candidate task to the writer using `kcmp(KCMP_VM)` and `kcmp(KCMP_FILES)`; equal results assign stable `mm_id`/`files_table_id` groups. The evidence records every comparison, permission result, and census boundary. The supervisor pins a dedicated cgroup-v2 leaf and exclusive migration authority, registers clone/fork/vfork/exec/exit tracing before exec, and denies new task creation and file-table sharing after the frozen worker set is established. At each output transaction it stops all other tasks sharing the target `mm_id` or `files_table_id`, rechecks the identities, and permits only the one transaction TID to proceed. An incomplete host-visible task census, unavailable/denied `kcmp`, an identity change, an untraced task birth, or a failed stop is open/missing; task count alone is not evidence. See [`kcmp(2)`](https://man7.org/linux/man-pages/man2/kcmp.2.html).

Every output-FD operation, including native read-only operations and `close`, enters the same arbiter. The trusted syscall supervisor records an entry stop, acquires the token, stops the sharing tasks, verifies the FD and open-file-description identity, then resumes only that TID. It records the matching exit stop before releasing the token. Broker-emulated open/write/pwrite/lseek operations acquire the same token before any side effect and retain it through notification response. A broker may hold a temporary `pidfd_getfd()` duplicate only while its token is active; it closes and records every such duplicate before token release. A target close cannot overlap a broker duplicate of the same open-file description. The target's final close and `FAN_CLOSE_WRITE` therefore map to the target operation; if the pinned kernel reports a different final-release actor, the attempt is unsupported until this relation is revised. The token serializes all output FDs, so aliasing or a shared `files_struct` cannot create a concurrent close/write race.

The supervisor uses a pinned syscall-entry/exit mechanism with exact kernel-version ordering relative to seccomp user notifications. For a `PTRACE_SYSCALL` profile, `PTRACE_O_TRACESYSGOOD`, `PTRACE_GET_SYSCALL_INFO`, clone/fork/vfork/exec/exit tracing, and every attach/stop/resume result are recorded; a seccomp notification and its target syscall entry/exit are distinct linked observations, never conflated. If the kernel produces a stop sequence not covered by the pinned profile, fail closed. The trace must preserve one target syscall sequence across its entry, notification (if any), result, and exit; any `SIGKILL`, task disappearance, interrupted notification, or missing exit leaves output retained and the attempt incomplete. Before any broker side effect, revalidate the notification ID after all argument/payload copies; revalidate again immediately before sending a spoofed result. A post-side-effect invalidation is recorded as a non-retryable incomplete attempt. See [`ptrace(2)`](https://man7.org/linux/man-pages/man2/ptrace.2.html) and [`seccomp_unotify(2)`](https://man7.org/linux/man-pages/man2/seccomp_unotify.2.html).

For the kernel-native read-only allowlist retained by V12, add exact `native_syscall_output_capture` rows `{io_token,syscall_sequence,syscall_nr,fd,open_file_description_id,user_address,requested_length,returned_length,abi_object_size,captured_bytes_base64,captured_bytes_sha256,copy_fault,exit_stop_id,mm_id}`. On successful `read/pread64`, `captured_bytes` contains exactly the bytes the kernel returned to the target buffer; on successful `fstat`, it contains exactly the pinned native-ABI `struct stat` output bytes. A failed or partial syscall records the exact kernel result and only the bytes proven written; if those bytes cannot be captured losslessly at the exit stop while all other `mm_id` tasks remain stopped, the attempt is incomplete. `fstat` uses the exact target ABI structure size/layout. These captures are not broker-generated and cannot be substituted by a caller-supplied hash. Scalar-only `lseek`, broker open/write results, and `close` have `copyout_ref=null`. This evidence separates native kernel copy-out from broker emulation and binds it to the same `io_token` and immutable target memory interval.

## 2. Single fanotify queue owner and event ordering

Replace V12 §3's responder/dispatcher split with a single trusted `fanotify_dispatcher` that exclusively owns and reads both the permission and name/notification group FDs and is the only process allowed to write permission responses. The broker never reads an event queue or approves its own `FAN_OPEN_PERM`; it sends the active `io_token` to the dispatcher over a bounded authenticated local channel. The dispatcher records one global `dispatch_sequence` over reads from both groups, raw event bytes, permission decisions/responses, and each drain boundary. Duplicated/inherited listener FDs, a second queue reader, or a second permission-response writer are denied by the supervisor FD inventory and leave the attempt open.

For broker `open*`, the broker records syscall entry and the exact transaction before entering the kernel. While the same `io_token` remains active, the dispatcher receives `FAN_OPEN_PERM`, checks actor pidfd/start time, output inode/path rule, and transaction ID, writes exactly one allowed response, and records its response syscall; only then may the broker open return and be cross-linked to the injected FD. For native target `read/pread64`, a matching `FAN_ACCESS_PERM` response is attached to the same token before syscall completion. Broker `write/pwrite64` `FAN_MODIFY` events identify the broker actor and map to that broker syscall, target request, and current token. Target `close` events identify the target actor and the traced target close sequence. Permission, FID/name, raw event, response, and syscall records retain V9/V10 wire schemas and are all joined through the token.

After each output syscall completes, while the arbiter remains locked, the dispatcher drains each subscribed group until `EAGAIN`, preserving a separate per-group sequence and one global dispatch sequence. No next output syscall starts before both drains complete. This makes any coalesced event attributable only to the current token and actor; an event whose raw semantics span multiple tokens, an event arriving after token release, an unmatched event, a queue overflow, an unexpected merge, or any loss leaves the attempt open. The pinned kernel profile defines the exact ordering of syscall exit, fanotify enqueue, permission response, and `EAGAIN` drain; if it cannot prove the event queue quiescent before release, this monitor design is unsupported. The target and broker cannot perform unobserved parallel operations during a drain. Linux documents that fanotify events can merge, so the one-token serialization and drain barrier are required, not optional. See [`fanotify(7)`](https://man7.org/linux/man-pages/man7/fanotify.7.html).

## 3. Full syscall-number universe and argument disposition

Replace V12's example list and “at minimum” clause. The current profile supports only the pinned native `AUDIT_ARCH_X86_64` ABI. The signed UAPI profile binds the exact kernel build, syscall-table/header bytes and hashes, word size, ABI, and the complete syscall-number universe, including unassigned holes. x32-number-bit calls and every other `audit_arch`/compat ABI are denied before dispatch; a host or binary requiring them is unsupported. Every number in the pinned universe has exactly one row, even if its disposition is unconditional deny. A number absent from the pinned UAPI table or introduced by another kernel version is denied and invalidates the profile.

`output_syscall_policy` is derived from that complete table and has exact rows `{audit_arch,syscall_nr,syscall_name_or_null,arg_words,args,fd_arg_indices,path_arg_indices,fd_effect,filesystem_effect,exact_predicates,disposition,record_source,output_io_token_required,exception_id}`. `args` defines all six ABI words, signedness, pointer direction, exact structure/version/size where applicable, and byte/count caps. `exact_predicates` mechanically decides whether each argument combination can address the output root, an output FD, its OFD aliases, mappings, process memory, or descriptor table. Dispositions are exactly `broker_emulated`, `deny_errno`, `static_allow_nonmutating`, or `allow_nonoutput_proven`; the last value is permitted only with a machine-checkable proof that the row's argument predicates cannot reach any output object. Every attempted syscall has one raw V9 `syscall_record`; every output-reachable operation additionally has one `output_io_arbiter` row. Missing rows, wildcard predicates, labels such as “metadata mutation” without exact operations, or unsupported argument layouts reject.

The generated table explicitly covers, for the pinned ABI, pathname opens/stat/enumeration (`open*`, `creat`, `newfstatat`, `statx`, `getdents64`, `readlink*`), all descriptor creation/duplication/passing/replacement/closure (`socket*`, `accept*`, `pipe*`, `eventfd*`, `memfd_create`, `pidfd_getfd`, `dup*`, `fcntl`, `sendmsg/recvmsg`, `close/close_range`, `execve*`), thread/process birth (`clone*`, `fork`, `vfork`), content and offset operations (`read/write`, positional and vectored variants, `lseek`, `sendfile`, `copy_file_range`, `splice/vmsplice`, `io_uring*`), mappings (`mmap`, `munmap`, `mremap`, `mprotect`, `pkey_mprotect`, `msync`, output-backed `madvise`), storage and metadata mutation (`truncate/ftruncate/fallocate`, `ioctl`, xattr, chmod/chown, timestamps, mkdir/rmdir/link/unlink/rename), and lock/sync operations. This list is a review checklist only: the signed table is generated for every syscall number, and the exact disposition/argument predicate for each number is authoritative. `close` has a separate `lifecycle_release` effect, never a “read-only” label. Only the V12 FD-bound `read/pread64/fstat/F_GETFL/F_GETFD/close` kernel-native exception may be `static_allow_nonmutating`; every such call requires its arbiter token, syscall-entry/exit evidence, and (for memory output) V13 copy-out capture. `lseek` remains broker-emulated and returns a scalar. No content mutation, pathname decision, or unprofiled syscall is continued with `SECCOMP_USER_NOTIF_FLAG_CONTINUE`.

The full UAPI table, predicates, seccomp bytecode, trace profile and supported ABI list share one canonical profile hash. Every static allow rule is tied to a fixed reserved-FD predicate and the output-I/O arbiter; every broker rule binds its exact syscall arguments to a transaction; every deny row records the kernel result. A change in the kernel syscall table, UAPI headers, audit architecture, seccomp action precedence, syscall-stop ordering, broker/dispatcher, or C++ runtime requires a fresh static review and profile.

## 4. Canonical raw maps snapshot and disjoint mapping partition

Replace V12 §4's separate range inventories with one canonical `initial_maps_snapshot` captured at `_dl_init` while the child and all `mm_id` peers are stopped. It has exact keys `{schema,pid,pid_start_ticks,stop_id,raw_base64,raw_sha256,byte_count,raw_row_count,parsed_rows_sha256,parsed_rows}`. `raw_base64` is the exact bounded byte stream read from `/proc/<pid>/maps`; the verifier reparses it independently. Each parsed row is `{raw_row_id,start,end,perms,file_offset,dev_major,dev_minor,inode,label_base64}`; `raw_row_id` is its one-based raw-line order, all raw scalar text re-encodes byte-for-byte, and the parsed rows hash is canonical over the ordered array.

Add `initial_map_partition={schema,raw_maps_sha256,record_count,records_sha256,records}` with exactly one row per `raw_row_id`: `{raw_row_id,primary_class,object_ref,virtual_mapping_ref,data_mapping_ref}`. `primary_class` is exactly `file_elf_exec`, `kernel_virtual`, or `data`; precisely the matching one reference is non-null. Each raw row occurs once and only once. `file_elf_exec` rows are file-backed executable ELF mappings represented by exactly one `initial_image_objects` mapping reference; `kernel_virtual` rows are exactly the supported vDSO/vvar/vsyscall classes; all remaining non-executable rows are `data`, including file-backed ELF data/relro, heap, stack and anonymous-private mappings. A data row may reference an ELF object for provenance but is never also an image mapping. Any executable data row, overlap, missing row, duplicate row, stale snapshot hash, or unknown class is missing/open.

Extend each `initial_image_objects` row with sorted unique `raw_row_ids` for its `file_elf_exec` rows. Each `initial_virtual_mappings.records` row adds one `raw_row_id` and reproduces the corresponding raw range, permissions, offset, device, inode and label exactly. Each `initial_data_mappings.records` row likewise adds one `raw_row_id`; its file-backed/anonymous nullability is fixed by `backing_kind` and it cannot claim immutable bytes for mutable memory. `initial_virtual_mappings` hashes remain required only for captured `vdso_elf` bytes; vvar/vvar-clock and emulated-vsyscall byte-hash fields are null as V12 specifies. `/proc/maps` source fields, including offset/dev/inode and label nullability, are taken from the raw row and cannot be independently invented by another inventory. The disjoint union of the three classes equals all rows in the canonical snapshot, and the executable subset equals the union of file-backed ELF executable mappings and supported kernel virtual executable mappings. See [Linux proc maps documentation](https://docs.kernel.org/filesystems/proc.html) and [`vdso(7)`](https://man7.org/linux/man-pages/man7/vdso.7.html).

## 5. Scope and authority

V13 is a design amendment only. It does not deploy or test the supervisor, tracer, broker, dispatcher, seccomp/fanotify profile or verifier; query host capabilities; run a binary; read production inputs; start GenCase/native/solver/worker/GPU/queue; connect evidence to a gate; or change registry/ledger/denominator/qualification credit. Independent read-only review is required. Host capability probes and every actual execution remain outside this static-review authorization.
