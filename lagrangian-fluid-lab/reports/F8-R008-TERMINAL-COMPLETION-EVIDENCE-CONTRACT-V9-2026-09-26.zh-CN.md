# F8 R008 Terminal Completion Evidence Contract v9

**Status:** additive proposal only; diagnostic-only; no solver/execution/readiness/qualification authority. Effective contract is v3 plus v4–v8 and this amendment. V1–V8 and all review records remain immutable. Required trust service, Linux supervisor, syscall/fanotify monitors, and verifier are not deployed.

V8 Terra High-config review: `REVISE`, no P0, identity not independently attested. V9 addresses the reported UAPI-mask, wire-schema, output-write-channel, task/cgroup-bound, loader-closure, and initial-image-timing findings. Where V9 conflicts with V3–V8, V9 controls; the earlier conflicting clauses are retained only as history. ## 1. Closed syscall ABI, output-write channels, and event wire format

Replace V8 §1. `output_seal_evidence` retains all V8 keys and additionally requires `syscall_abi_profile`; `fanotify_profiles` replaces all prior singular or dual-group descriptions. The signed evidence contains exact-keyed `syscall_profile`, `syscall_abi_profile`, `syscall_records`, `fanotify_profiles`, and `fanotify_raw_events`. Every object/row has `additionalProperties=false`.

`syscall_abi_profile` is `{schema,profile_id,profile_sha256,audit_arch,word_bits,byteorder,entries}`. `profile_sha256` is SHA-256 over the versioned canonical JSON bytes of the object with that field omitted. Its canonical signed `entries` array is sorted by syscall number and has exactly one row for every allowed or denied syscall number in the attempt. Each row is `{syscall_nr,syscall_name,phase_mask,arg_words,args,result_kind,effect,fd_arg_indices,path_arg_indices,io_policy}`. `syscall_nr` is a nonnegative ABI syscall number; `syscall_name` is the exact pinned UAPI name; `phase_mask` is a nonempty sorted unique subset of `writer,seal,verify`; `arg_words` is 0..6. `args` has exactly six ordered slots `{index,kind,signed}` with `index=0..5`; slots below `arg_words` have non-`unused` kinds and all later slots are `unused` with `signed=false`. Kinds are from the closed enum `unused,word,signed_word,fd,dirfd,path,buffer,count,flags,mode,offset,pid,struct_ptr`; `signed` is a JSON boolean and is true only for signed ABI words. `fd_arg_indices` and `path_arg_indices` are sorted unique arrays mechanically derived from the corresponding argument kinds. `result_kind` is `integer,fd,void`; `effect` is from V8's closed enum; `io_policy` is `none,write_prefix,output_write,fanotify_response`. The profile explicitly defines every argument index, phase, return interpretation, FD/path argument, and I/O policy for the pinned architecture. Duplicate numbers/names, a syscall number appearing in a trace without a profile row, or a profile hash not pinned by the frozen external dependency policy rejects.

`syscall_records` retains the V8 top-level fields and adds `cwd_ref`, replacing nested FD rows with exact `{arg_index,fd,dev,ino,mount_id,file_description_id,access_mode,status_flags,position_before,position_after}`; result-FD rows are exact `{fd,dev,ino,mount_id,file_description_id,access_mode,status_flags}`. Descriptor indices/FDs are signed-32, identity/offset fields are unsigned-64 or explicitly nullable only when the pinned operation has no file position, `access_mode` is one of `read_only,write_only,read_write,path_only`, and each positive `file_description_id` is a monitor-assigned stable token for one open-file description (not an FD number), unique and never reused within the attempt. FD rows are sorted by `arg_index`. Applicability is mechanically derived from the matching `syscall_abi_profile.entries` row: `fd_refs` contains exactly one row for every argument whose kind is `fd` or a non-`AT_FDCWD` `dirfd`; `path_refs` contains exactly one row for every `path` argument; `result_fd` is non-null iff `result_kind=fd` and the syscall succeeds; `effect` equals the profile row; `phase` is a member of `phase_mask`; and `io_prefix_base64` follows the exact capture rule identified by `io_policy`. `cwd_ref` is null unless a path argument uses `AT_FDCWD`; then it is exact `{dev,ino,mount_id,file_description_id}` for the separately held cwd descriptor resolving the task's cwd at syscall entry. In the matching V8 `path_refs` row, `dirfd=-100` and `dirfd_dev/ino/mount_id` are null; the independent `cwd_ref` supplies its identity. For `io_policy=none`, `io_prefix_base64` is null; `write_prefix` and `output_write` capture the specified first `min(64,requested_count)` bytes; `fanotify_response` captures exactly the 8 native ABI response bytes. For a failed syscall, `errno` is the positive ABI errno and `exit_value=-errno`; for success, `errno=0` and the raw return is decoded per `result_kind`. `entry_args_base64` is exactly six words in the pinned ABI byte order. Every nested `path_refs` and statx row retains V8's exact schema and ABI scalar bounds; regular-file offsets are unsigned-64 or null only when the operation has no file position. `fanotify_sequences` replaces V8's integer list with sorted unique `{group_id,sequence}` references, ordered by `permission_group` then `name_group` and event sequence; it is exactly the inverse of the corresponding raw-event `syscall_sequences` relation.

For **output-mount file contents**, the only permitted mutating operations are sequential `write` and positioned `pwrite64` to a registered regular-file FD in the writer cgroup. Output-FD opens reject `O_APPEND|O_TRUNC`; `open_by_handle_at`, `lseek` on an output FD, `writev`, `pwritev`, `pwritev2`, `sendfile`, `copy_file_range`, `splice`, `vmsplice`, all `io_uring` setup/submit/register, `fallocate`, `truncate`, `ftruncate`, content-mutating `ioctl` (including clone/dedupe/range operations), `madvise(MADV_REMOVE)` on an output-backed mapping, writable file-backed mmap (including writable `MAP_PRIVATE`), shared writable mappings, and any unprofiled content mutation are denied and recorded. `mprotect`/`pkey_mprotect` are denied whenever they could add write access to an output-backed shared mapping; the monitor tracks mapping provenance from `mmap` through `munmap`/protection changes. For `write`/`pwrite64`, `io_prefix_base64` is a bounded diagnostic sample: it contains the first `min(64,requested_count)` bytes copied at syscall-entry stop while every other writer TID is stopped; it is not claimed to capture the remainder of a large call. The successful return count selects the prefix bytes attributable to that call. Descriptor provenance and exact current/explicit offsets, the sealed final file hashes, and the source-level BI4 header event jointly bind accepted output. For BI4, the concatenation at offsets 0..63 must equal the independently parsed 64-byte logical header; this header-specific proof makes no claim that a 64-byte sample authenticates later file content. Any gap/overlap in the claimed header, non-write content change, writable mapping, vectored/copy/async path, or unobservable syscall rejects. Path creation/removal/rename and metadata operations remain separately monitored through exact path arguments, fanotify records, and before/after inode state; none can substitute for the header-byte write proof.

`syscall_profile` is exact `{schema,monitor_sha256,audit_arch,abi_profile_id,syscall_allowlist,syscall_denylist,coverage_start_ns,coverage_stop_ns,record_count,records_sha256,lost_records,max_records}`. Allow/deny arrays are sorted, unique and disjoint; their union exactly equals `syscall_abi_profile.entries.syscall_nr`. Every raw attempt is recorded, including denied operations. Sequence starts at 1, is contiguous, timestamps strictly increase, record count equals array length and is ≤1,000,000, evidence bytes ≤64 MiB, `lost_records=0`, and `records_sha256` is SHA-256 of the canonical ordered rows. Unknown syscalls are denied. `termination_watch.events[*].fanotify_sequences` uses the same exact `{group_id,sequence}` references, and its `syscall_sequence` is the unique source row from which that projection is derived; no integer-only sequence may be interpreted across the two independent group streams.

### fanotify group profiles and rows

The groups have distinct monitor-assigned watcher IDs. Exact `fanotify_profiles` keys are `{permission_group,name_group}`. Each group profile has exactly the full V8 profile key set plus `{group_id,event_count,events_sha256}`; `group_id` is exactly `permission_group` or `name_group`, and `watcher_id` is a distinct positive unsigned-64 monitor-assigned ID (it is not a kernel field). `output_seal.watcher_id` and `termination_watch.watcher_id` identify `name_group.watcher_id`; `permission_group.watcher_id` is separately bound in the signed evidence and must differ. `event_count` is 0..1,000,000; `events_sha256` is lowercase SHA-256 of the canonical sequence-ordered raw rows. Each raw event has exactly one `group_id` and `watcher_id` equal to the selected profile's watcher ID. Sequence is per group, starts at 1, is contiguous, and ends at that profile's `event_count`; an empty stream has count zero and SHA-256 of the canonical empty array. Permission and name raw streams are separately ordered; no interleaving is inferred. Overflow, a count/hash mismatch, or any unsupported UAPI feature rejects.

`permission_group` remains `FAN_CLASS_CONTENT|FAN_REPORT_PIDFD`, with no FID/name-report flags, and exactly `FAN_OPEN_PERM|FAN_ACCESS_PERM|FAN_OPEN_EXEC_PERM`. The event metadata PID is signed-32 in `1..INT32_MAX`; the single PIDFD info record's FD resolves to the same live PID and start ticks. Permission-row `metadata_fd` is signed-32 `>=0` and fstat/statx-bound to the event object. `response` is exactly `FAN_ALLOW=1` or `FAN_DENY=2`; `response_syscall_sequence` is required and unique. That referenced syscall must be a successful write of exactly one native-ABI `struct fanotify_response` (8 bytes: signed-32 FD equal to `metadata_fd`, unsigned-32 response equal to the recorded enum); the captured `io_prefix_base64` equals those exact eight bytes. Permission requests are allowed only by the frozen actor/phase/path policy; all others are denied.

`name_group` remains `FAN_CLASS_NOTIF|FAN_REPORT_PIDFD|FAN_REPORT_DFID_NAME_TARGET`, no permission-event bits, but V9 **replaces V8's `FAN_MARK_MOUNT` with `name_group.mark_type=FAN_MARK_FILESYSTEM`**: Linux rejects FID-dependent `FAN_CREATE`, `FAN_ATTRIB`, and related masks on a mount mark. `name_group.mark_flags=FAN_MARK_ONLYDIR`; `FAN_REPORT_MNT` is absent because Linux rejects it in combination with `FAN_REPORT_DFID_NAME_TARGET`. The output must therefore be a dedicated fresh tmpfs superblock with one mountpoint in the supervisor's private mount namespace, private propagation, and no bind/clone/move of that mount or filesystem to any other namespace; the supervisor records the mount-namespace and mountinfo evidence proving this invariant. A pre-run host capability fixture must also establish a stable nonzero tmpfs `fsid` and successful fanotify file-handle encoding for the pinned kernel; unsupported FID/fsid behavior leaves the attempt missing/open. The filesystem mark is applied to the output root; inability to prove the filesystem instance has no other mountpoint makes event attribution missing/open. The profile's `mount_id` identifies that sole output mount; each name-group event is bound to it by the unique filesystem `fsid`, event FID/DFID, syscall path and held namespace/mount snapshots, not by a nonexistent event `mnt_id`. Its exact `event_mask` is the six event-type bits `FAN_CREATE|FAN_DELETE|FAN_RENAME|FAN_MODIFY|FAN_CLOSE_WRITE|FAN_ATTRIB` plus the `FAN_ONDIR` mark modifier required to report events on directory objects. No `FAN_MOVE`, `FAN_MOVED_FROM`, `FAN_MOVED_TO`, `FAN_MOVE_SELF`, or other event type is subscribed; rename coverage uses the distinct `FAN_RENAME` event. `event_info_profile` has one row for each of the six event-type bits, never for `FAN_ONDIR`. On returned events, `FAN_ONDIR` is the sole permitted modifier bit; the parser verifies the event's target object is a directory according to the pinned event profile. No other returned mask bit is accepted. `event_info_profile` has exact keys `{schema,profile_sha256,records}`; its canonical hash excludes `profile_sha256`, and its `profile_sha256` equals the containing `name_group.event_info_profile_sha256`. `records` is an array of exact rows `{mask,required_info_types,optional_info_types,accepted_record_orders}`; there is one row per individual event-type bit and no others. Types are sorted unique numeric UAPI values. Each `accepted_record_orders` item is one complete ordered list of distinct record types; it contains every permutation of the required set and every permitted optional subset, and no other list. The list is capped at 720 orders per event bit. For combined event masks, required/optional sets are unioned by bit and the raw list must be one accepted permutation of that union:

| Event bit | Required information records |
|---|---|
| `FAN_CREATE`, `FAN_DELETE` | exactly one `PIDFD`, `FID` (target child), and `DFID_NAME` |
| `FAN_RENAME` | exactly one `PIDFD`, `FID` (target child), `OLD_DFID_NAME`, and `NEW_DFID_NAME` |
| `FAN_MODIFY`, `FAN_CLOSE_WRITE`, `FAN_ATTRIB` | exactly one `PIDFD` and `FID`; `DFID_NAME` is optional only under the no-parent rule below |

For combined event masks, the row's required set is the union of the per-bit sets and no required record can be omitted. A missing `DFID_NAME` on an object event is accepted only if the pinned kernel/filesystem profile establishes that the affected inode has no parent and the FID maps to an inode with a unique earlier syscall-recorded output path/removal lineage; otherwise it rejects. Every supplied DFID/name resolves to the corresponding syscall path. `FAN_RENAME` old/new records must both parse and match the two path arguments; the target FID must equal the affected inode. External/out-of-mount rename targets reject. Linux fanotify can merge consecutive same-object/same-origin non-permission events into one queue entry, so the syscall trace remains authoritative and event-to-syscall correlation is many-to-many; this contract makes no one-event-per-syscall claim. A merged event is accepted only when its complete compatible syscall set and info-record/path semantics are uniquely derivable; otherwise the attempt remains missing/open rather than guessing. The pinned API behavior for event masks, directory modifiers, and merge behavior is cross-checked against [fanotify(7)](https://man7.org/linux/man-pages/man7/fanotify.7.html) and the exact Linux UAPI header hash.

Each raw event has exact keys `{group_id,watcher_id,sequence,monotonic_ns,raw_base64,raw_sha256,event_len,metadata_len,metadata_version,metadata_reserved,metadata_fd,mask,event_pid,pidfd_resolved_pid,pid_start_ticks,info_records,syscall_sequences,response,response_syscall_sequence}`. `group_id` selects exactly one profile; `watcher_id` equals that profile's watcher ID. Per-group sequence is positive unsigned-64; `monotonic_ns` is sampled by the monitor immediately when the corresponding `read()` returns and is strictly increasing within that group; raw bytes are canonical base64 ≤64 KiB and hash-match; `event_len` equals decoded bytes; metadata version/length/reserved equal the pinned ABI and reserved is zero. The parser rederives every decoded field from raw bytes. `event_pid` is signed-32 `1..INT32_MAX` and equals the live PID resolved by `pidfd_resolved_pid`; `pid_start_ticks` binds the same task. After separating `FAN_ONDIR`, `mask` has a nonzero subset of the profile's subscribed event bits; combined bits use the union rule above. `metadata_fd` is signed-32. For name-group FID events, `metadata_fd=FAN_NOFD (-1)` and response fields are null. For permission-group events it is nonnegative, response is exactly `FAN_ALLOW=1` or `FAN_DENY=2`, and `response_syscall_sequence` is a positive sequence referencing the unique valid response-write record. `syscall_sequences` is a nonempty sorted unique array of positive syscall-trace sequence IDs that caused or were coalesced into this event; permission events reference exactly their one causative syscall, while name events may reference multiple compatible calls. It is exactly inverse to syscall-record `fanotify_sequences`. Info rows are exactly `{info_type,length,pad,payload_base64,payload_sha256,decoded}`; `info_type` is u8, `length` is u16 including the 4-byte information header and equals the raw record length; `pad=0`; `payload_base64` and its hash cover exactly the bytes after that header. PIDFD decoded row is exactly `{pidfd_fd:s32}` and the descriptor binds to the resolved live PID; FID/DFID row is `{fsid_base64:8_bytes,handle_type:s32,handle_bytes_base64:length_from_file_handle}`; each DFID_NAME variant adds exactly `{name_base64}`. File-handle bytes are ≤128; a name is 1..255 non-NUL bytes followed by exactly one NUL. No duplicate/missing required type, type order outside `accepted_record_orders`, invalid length, unsupported type, bad PIDFD, trailing bytes, or UAPI-version mismatch is accepted. `FAN_Q_OVERFLOW` is never accepted as an ordinary event; any overflow event or nonzero profile `overflow_count` rejects. Raw order is retained and its list of types must equal one accepted sequence; pathname semantics are cross-checked separately.

## 2. Close task, process-group, and cgroup cardinality

Replace V8 §2 and extend the V6 raw evidence keys with `cgroup_threads_before` and `cgroup_threads_after`, each typed exactly like the other bounded cgroup raw-byte records. Nested cgroups are forbidden. Before writer teardown, the before records contain the complete `cgroup.procs` leader-PID set and complete newline-terminated `cgroup.threads` TID set; after teardown, `cgroup.procs` and `cgroup.threads` are both exactly empty and `cgroup.events` says `populated 0`. Raw ID lines are positive decimal Linux IDs with no duplicates, no leading zeros, and a final LF; raw order is preserved but not relied upon. The verifier sorts parsed IDs numerically for exact set comparisons. `cgroup.procs` is independently parsed as the process-leader PID set and must equal the unique PID projection of `cgroup.threads`. Thus the evidence contains six raw snapshots: `cgroup.procs`, `cgroup.threads`, and `cgroup.events` both before and after teardown. Each raw snapshot retains the V6 exact `{raw_base64,raw_sha256}` schema and 1 MiB bound; a separate exact descriptor observation binds all six reads to the same held cgroup directory FD and its `fstat`/`statx` `{dev,ino,mount_id}` identity. Read syscall sequences and monotonic times are recorded in the common syscall trace; no duplicated caller-asserted FD field is accepted in the raw object.

Replace `task_snapshot_before/after` row schemas with exact `{pid,pid_start_ticks,tid,tid_start_ticks,mount_namespace_inode,cgroup_dev,cgroup_ino,cgroup_mount_id,state,pgrp,session,proc_stat_base64,proc_stat_sha256}`. Each row is one Linux TID, sorted by `(pid,pid_start_ticks,tid,tid_start_ticks)`. Raw proc bytes come from `/proc/<pid>/task/<tid>/stat`; decoded PID/TID/start ticks/state/pgrp/session equal the row. `task_snapshot_before` TID set exactly equals `cgroup_threads_before`; `task_snapshot_after` contains every host-visible TID whose mount namespace equals the sealed output namespace or whose FD table holds that namespace, and only the registered verifier/supervisor/monitor roles may appear. The inherited `namespace_fd_records` keeps exact rows `{pid,start_ticks,fd,namespace_inode}` and is exhaustive for every host-visible process FD resolving to that mount namespace; each row resolves to the same held namespace identity and a corresponding task-snapshot process identity. No writer task/descendant or unregistered process may remain. Each snapshot count equals its array length and is ≤65,536; unreadable tasks, PID/TID reuse, omitted descendants or unexpected namespace/FD holders reject. The host scan and FD enumeration use held proc descriptors, pidfds, a monotone scan interval and explicit inaccessible-entry failure; they cannot be represented by a single unverified `/proc` pathname walk.

`process_group_observations` is exactly `{schema,record_count,records_sha256,records}`; `schema=core.cfd.f8.r008.process_group_observations.v1`. `records` is sorted by phase rank then `(pid,pid_start_ticks,tid,tid_start_ticks)` and has exact rows `{phase,pid,pid_start_ticks,tid,tid_start_ticks,pgrp,session,proc_stat_base64,proc_stat_sha256,cgroup_dev,cgroup_ino,cgroup_mount_id}`. `phase` is exactly `pre_exec,child_start,task_snapshot_before,task_snapshot_after`. There is exactly one `pre_exec` row for the launched child leader, sampled before `execve`; exactly one `child_start` row for every TID in the complete writer `cgroup.threads` census at the first post-exec ptrace stop; and exactly one row per task in each named task snapshot. Later thread births are represented only by the complete `thread_events` rows and then by the before-teardown task snapshot. Per-phase rows equal the corresponding syscall/task snapshot records by identity and raw-stat hash; no extra rows or duplicate identity rows are allowed. `record_count` equals length (1..65,536), and `records_sha256` hashes the canonical ordered rows. PID/TID are positive signed-32 IDs; start ticks are positive unsigned-64; pgrp/session are positive signed-32 IDs; cgroup dev/inode/mount IDs are unsigned-64. Raw proc bytes are ≤4096 and SHA-256-matched. `output_seal.process_group_id` equals the child's observed pgrp at `child_start`, and every writer TID shares that process group/session. `writer_cgroup_inode` equals the fstat inode of the single held cgroup directory FD; device and mount IDs match all cgroup reads. `task_snapshot_after` also includes the exhaustive post-teardown host scan and the exact V6 `namespace_fd_records` for every process descriptor referring to the sealed mount namespace; the scan is bounded, PID-reuse checked, and contains only registered verifier/supervisor/monitor roles. Cgroup sets, task census, proc bytes, wait/reap table and raw syscall trace must close exactly; any mismatch returns missing/open.

## 3. Correct the runtime-guard scope and sampling point

Replace all V7/V8 runtime-guard and initial-image sampling language. The phrase “first instruction after execve” is superseded: the executable and DT_NEEDED objects are not all mapped at that point. This profile accepts only the pinned dynamically linked CPU binary and captures `initial_image_objects` at a trusted stop on entry to the pinned dynamic linker's `_dl_init`, after the initial dependency set has been loaded/relocated and before the executable's preinit array or dependency init arrays execute. The stop address, loader build ID, byte sequence and control-flow location are in the hashed ABI-specific runtime profile. If that exact pre-user-initialization point cannot be located and attested, the attempt is missing/open. Static binaries use no implicit fallback; they require a separately versioned profile.

Replace V8's `loader_entrypoints` completeness claim based only on dynamic/version symbol tables. `loader_profile_sha256` binds a complete machine-code loader-capability profile: pinned ELF objects and build IDs; debug-symbol files; disassembler binary/version/hash; complete executable code ranges; parsed dynamic/version symbols; local/hidden/stripped/IFUNC targets; instruction bytes at every entry/call site; direct-call edges; all indirect-call sites and their closed target sets; and relocation/PLT/GOT resolution data. `loader_entrypoints` includes every exported/versioned API and every local/internal/compiler-generated target in this profile that can load an object, create a loader namespace, or resolve a symbol. The monitor plants/verifies traps at every listed address before application code starts and records all hits. An unresolved indirect target, missing debug/disassembly data, mutable code page, new executable mapping, uninstrumented target, or unprofiled loader-capable path is missing/open; no claim of completeness is inferred from `.dynsym` alone.

Replace V8 `runtime_guard` with exact keys `{schema,loader_profile_sha256,loader_disassembly_profile,initial_image_capture,seccomp_profile_sha256,monitor_sha256,coverage_start_ns,coverage_stop_ns,initial_image_objects,loader_trap_registrations,loader_events,process_syscalls,executable_mapping_events,thread_events,lost_records}`; retain V8 row contracts only where this section does not replace them. `loader_profile_sha256` equals the `profile_sha256` of exact `loader_disassembly_profile` keys `{schema,profile_id,profile_sha256,disassembler_sha256,disassembler_version,debug_symbols_sha256,loader_build_id,root_operations,objects,executable_sections,entrypoints,call_edges,indirect_call_sites,unresolved_target_count}`; each hash omits only its own `profile_sha256` field before canonical hashing. Every list has ≤65,536 rows and a specified order: objects by `object_sha256`; executable sections by `(object_sha256,file_offset,section_name)`; entrypoints by `(object_sha256,file_offset,entrypoint_id)`; call edges by `(caller_entrypoint_id,instruction_offset,target_entrypoint_id)`; indirect sites by `(object_sha256,instruction_offset)`; root operations by `operation_id`. `unresolved_target_count` is exactly zero. Each object row is `{object_sha256,build_id,debug_object_sha256}` with required nonempty build ID and debug-object hash. Each executable section row is `{object_sha256,section_name,file_offset,size_bytes,section_sha256}` and must lie wholly inside an object in the profile. Each entrypoint row is `{entrypoint_id,object_sha256,build_id,file_offset,virtual_address,size_bytes,kind,symbol,version,visibility,instruction_sha256}`; IDs are unique and are 64-hex SHA-256 of the versioned canonical `{object_sha256,file_offset}` pair; symbol is nonempty printable ASCII or null only where neither ELF nor debug data provides a label; version is null for unversioned targets or a nonempty printable-ASCII version label. `kind` is `exported_api,versioned_api,hidden_api,local_internal,ifunc_resolver,loader_internal`; `visibility` is `default,protected,hidden,local`. `instruction_sha256` hashes exactly the first complete machine instruction at the entrypoint; `size_bytes` is the profiled function/code extent. Every offset/range lies in a listed executable section and virtual address is derived from pinned ELF load segments. Each direct/PLT/IFUNC/tail edge row is `{caller_entrypoint_id,instruction_offset,instruction_sha256,target_entrypoint_id,edge_kind}` with `edge_kind=direct,plt,ifunc,tail`; every row binds exact instruction bytes and both endpoints. Each indirect-call row is `{object_sha256,instruction_offset,instruction_sha256,resolution_method,targets,complete}`; `resolution_method` is a closed pinned-profile enum; targets are exact sorted `{object_sha256,entrypoint_id,virtual_address}` rows, unique and within the executable closure; `complete=true` only when the pinned relocation/data-flow analysis proves the full target set. Each `root_operations` row is exactly `{operation_id,operation_kind,entrypoint_id,object_sha256,denial_policy}`; operation ID is unique and deterministic from its operation kind and entrypoint ID; operation kind is `object_load,namespace_create,symbol_resolution`, and denial policy is exactly `deny_after_initial_capture`. The list contains every loader-capable operation and every associated local/internal alias in the pinned machine-code/control-flow profile. Any missing executable section, unresolved indirect target, duplicate target, writable-executable page, unprofiled loader-capable path, or hash/build-ID mismatch leaves evidence missing/open. This inventory is derived from the pinned full object code/debug/disassembly and relocations, not `.dynsym` alone.

`initial_image_capture` is exactly `{schema,pid,pid_start_ticks,tid,tid_start_ticks,stop_trace_sequence,object_sha256,build_id,stop_symbol,stop_file_offset,stop_virtual_address,stop_instruction_sha256,stop_monotonic_ns,maps_raw_base64,maps_raw_sha256,preinit_not_started,constructors_started_count,monitor_sha256}`. `pid/tid` are positive signed-32 and start ticks are positive unsigned-64; `stop_trace_sequence` resolves to the one trusted ptrace stop. `stop_symbol` is the pinned dynamic linker's `_dl_init` entry; `preinit_not_started=true`; `constructors_started_count=0` means no executable preinit or dependency init function has started (it does not mean the binary contains zero constructors). `maps_raw_base64` is the ≤1 MiB exact `/proc/<pid>/maps` byte snapshot read through held proc descriptors while the child is stopped, and its SHA-256 matches; parsed executable mappings equal `initial_image_objects` exactly. The trace proves all initial dependency objects are already mapped/relocated and the stop occurs before `_dl_init` invokes executable preinit or dependency init arrays. The `initial_image_objects` snapshot timestamp equals this stop timestamp, and every executable mapping is bound to an object/section in `loader_disassembly_profile`. `initial_image_objects` is sorted by `(object_sha256,mount_id,device,inode)` and contains exact rows `{object_sha256,build_id,device,inode,mount_id,size_bytes,mode,mapped_ranges}`; every identity/size is unsigned-64, `mode` is exact `st_mode` and must denote a regular file, build ID is nonempty lowercase hex, and each mapped range is exact `{start,end,file_offset,prot_bits}` with unsigned-64 values, `start<end`, no overlap, strictly start-sorted, and `prot_bits` limited to `PROT_READ|PROT_WRITE|PROT_EXEC` with EXEC set. Every object and executable mapping is a member of the frozen initial closure, its held-FD hash/build ID/inode/device/mount match the runtime profile, and all executable bytes are covered by listed sections. The array contains one row per mapped executable object, not one row per segment.

`loader_trap_registrations` is the exact array `{sequence,entrypoint_id,object_sha256,build_id,file_offset,virtual_address,instruction_sha256,trap_mechanism,monitor_sha256}`; there is exactly one row for each unique `root_operations.entrypoint_id`, sorted by sequence from 1 with no gaps. `trap_mechanism` is a closed enum pinned by the monitor profile: `kernel_uprobe` or `hardware_exec_breakpoint`; it must preserve immutable application text, expose no writable-executable alias, and provide complete loss-free entry coverage. Registration binds the original instruction bytes/address and is active before the first dynamic-linker instruction after exec; the verifier independently confirms it before resuming the child. `loader_events` rows are exact `{sequence,monotonic_ns,phase,pid,pid_start_ticks,tid,tid_start_ticks,entrypoint_id,caller_object_sha256,callsite_offset,callsite_sha256,args_base64,action,result,syscall_sequence,trap_registration_sequence}`. `phase` is `bootstrap` or `guarded`; `action` is `allowed_frozen_initial` or `denied`. During `bootstrap` (exec through the `_dl_init` stop), only initial object loading and relocation/symbol resolution strictly within the frozen source/runtime closure may be allowed; namespace creation is denied. During `guarded` (at/after the stop), every root operation is denied. `result` is the pinned success/denial result consistent with action; `args_base64` is the exact bounded raw argument block decoded per the root operation; syscall sequence is null only if the event has no corresponding syscall, otherwise references that exact syscall record. Caller object/callsite are null only for the first dynamic-linker entry from the kernel transfer point; otherwise both resolve to a pinned executable range. Every hit on a registered address has exactly one event and every event references one registration. The `_dl_init` sampling stop has its own exact breakpoint observation in `initial_image_capture`; it is not a root-operation trap and is consumed exactly once before the guarded phase resumes. After the stop, no new object/namespace, symbol-resolution operation, executable mapping, code-page write, or untrapped target is allowed. Unresolved profile items, trap misses, missing debug/disassembly data, or an unobservable loader-capable path are missing/open, never inferred absent from an empty event array.

All other V8 process syscall, executable mapping, and thread-birth row sets remain closed by their prior schemas and common byte/count bounds, now cross-linked to this full loader profile and V9 syscall ABI profile. No new object or loader namespace is allowed after the pre-constructor stop.
