# F8 R008 Terminal Completion Evidence Contract v11

**Status:** additive proposal only; diagnostic-only; no solver/execution/readiness/qualification authority. Effective contract remains v3 plus v4–v10 and this amendment. V1–V10 and review records remain immutable. No trusted I/O broker, Linux supervisor, syscall/fanotify monitor, or verifier is deployed.

V10 review result: `REVISE`, no P0. The review confirmed the fresh-output/append and eager-binding corrections at the design level, but found that `SECCOMP_USER_NOTIF_FLAG_CONTINUE` still cannot serve as a security policy and that the initial executable-map schema incorrectly classifies the kernel-provided vDSO as a regular file. It also found that V10 had not made its expected path set/root-external-link proof fully auditable. Reviewer model identity was not attested. V11 replaces those clauses without changing F8's case matrix, terminal semantics, trust roots, qualification gates, zero-credit boundary, or authorization.

## 1. Broker output I/O; no `CONTINUE` for output-sensitive calls

Replace V10 §2's `continue_one` output-syscall gate and revise V10 §1's output lifecycle evidence as specified here. `SECCOMP_USER_NOTIF_FLAG_CONTINUE` is never used for an output-path or output-FD syscall. Seccomp notification is a broker request/serialization mechanism, not the security boundary. The Linux seccomp documentation explicitly warns that `CONTINUE` has pointer-argument TOCTOU exposure, can be bypassed by higher-precedence filter layering, and must not implement security policy; the pinned profile therefore emulates or denies each mediated syscall and never continues it into the target kernel path. See [seccomp_unotify(2)](https://man7.org/linux/man-pages/man2/seccomp_unotify.2.html).

The writer starts in a dedicated mount namespace whose root and every non-output mount are read-only. The only writable filesystem visible to the writer is the fresh, dedicated output tmpfs. The signed kernel-enforcement profile denies mount/namespace changes, direct content-changing syscalls, writable output mappings, output `ioctl`, `open_by_handle_at`, and every unprofiled filesystem mutation. It also denies later `seccomp()` and `prctl(PR_SET_SECCOMP)` filter installation; the initial filter is installed before `execve` with `no_new_privs`, thread synchronization, and an exact per-TID inherited-filter count. The seccomp action/profile precedence and every inherited filter are recorded. Catchable writer signals are blocked by the frozen signal-mask profile; signal-action/mask changes are denied. `SIGKILL`/task disappearance during a broker request makes the attempt incomplete. Any unexpected tracer, ptracer, process-memory writer, nested filter, signal handler, or writable mount leaves the attempt missing/open. The output mount and syscall-deny layer remain effective independently of broker path validation.

Add exact `io_broker_profile` keys `{schema,broker_sha256,broker_runtime_sha256,seccomp_profile_sha256,syscall_abi_profile_sha256,output_root_fd_token,output_mount_id,output_dev,output_ino,reserved_target_fd_range,emulated_syscall_nrs,denied_syscall_nrs,filter_chain,signal_policy,record_cap,byte_cap,profile_sha256}`. Its canonical hash omits only `profile_sha256`. `emulated_syscall_nrs` and `denied_syscall_nrs` are sorted unique disjoint syscall-number sets whose union equals the profile's complete output-sensitive set. No output-sensitive syscall is `ALLOW` or `CONTINUE`. `filter_chain` binds the exact initial filter bytes/hash and load order, and proves no pre-existing unpinned filter. The reserved target-FD range is finite, nonoverlapping with inherited control FDs, and the broker assigns only within it. The BPF profile routes pathname operations and operations on a reserved output FD to notification; direct operations capable of mutating output are denied. Duplicating/receiving an output FD is denied unless separately broker-emulated with a new reserved FD and exact shared-open-description lineage. A changed kernel, seccomp ABI, broker, C++ runtime, or output root requires a fresh profile.

Each intercepted writer request has exactly one `writer_syscall_gate` row with keys `{sequence,notification_id,pid,pid_start_ticks,tid,tid_start_ticks,audit_arch,syscall_nr,entry_args_sha256,policy_bytes_sha256,dispatch_mode,broker_transaction_id,syscall_sequence,response_kind,response_value,response_errno,response_flags,notification_id_validated,lost_records}`. `dispatch_mode` is `broker_emulated` or `deny_errno`; `continue` is not an enum value. A successful broker-created open uses `SECCOMP_IOCTL_NOTIF_ADDFD` with `SECCOMP_ADDFD_FLAG_SEND`, atomically installing the broker-opened descriptor in the target and returning that FD number. All other emulated operations return a spoofed result with `flags=0`; exact value/error encoding follows the pinned native seccomp ABI. Every row binds one target syscall record, one valid notification ID, and either one broker transaction or one denial. No side effect is accepted unless the same notification ID remains valid immediately before dispatch and the response is successfully committed. If the target exits, is signal-interrupted, or invalidates the notification during dispatch, any already-performed broker side effect remains in the attempt transcript, the output tree is retained, and the attempt is incomplete/non-retryable; no cleanup or qualification inference follows.

The broker never keeps a persistent writable duplicate of a target output FD after `ADDFD_FLAG_SEND`: it closes its source FD immediately after injection. For a later mediated `read`, `write`, `pread64`, `pwrite64`, `lseek`, or `fstat` on a reserved target output FD, the broker obtains a temporary FD with `pidfd_getfd()` while the target syscall is blocked and sibling writer TIDs are stopped. The temporary FD refers to the same open file description, status flags, and file offset as the target FD; the broker performs the exact supported operation and closes the temporary FD before returning a spoofed result. A failed identity/permission check, unavailable `pidfd_getfd`, unsupported ABI, or output FD outside the reserved range rejects the operation. `close` may execute under the kernel's static allow rule because it only releases a target descriptor and does not access or mutate file content; the broker holds no duplicate that could delay the target's final `FAN_CLOSE_WRITE`. See [seccomp_unotify(2)](https://man7.org/linux/man-pages/man2/seccomp_unotify.2.html) and [pidfd_getfd(2)](https://man7.org/linux/man-pages/man2/pidfd_getfd.2.html).

For an output `open/openat/openat2/creat` request, the broker copies and hashes the pathname and exact ABI arguments while the target is blocked, resolves it relative to the held output-root FD with the pinned no-symlink/beneath resolution rules, and matches the finite signed path grammar. A fresh create requested by C++ `O_CREAT|O_TRUNC` is implemented by the broker with an exclusive create (`O_CREAT|O_EXCL`, no `O_TRUNC`) on a proven-absent leaf. If the leaf exists, the broker denies the request. A later append open is implemented only for its allowlisted inode with `O_APPEND`, no truncate flag, and the source-profile access mode. The broker passes the created/open file description through `ADDFD_FLAG_SEND`, then closes its local FD. No writer kernel syscall ever truncates an existing file. The pre-run path set is made auditable by exact `path_rule_id` expansions `{path_rule_id,root_role,path_bytes_base64,path_sha256,source_emission_id,expected_state,max_occurrences}`: all required parent directories have pinned dev/inode/mount identities; every governed output leaf has `expected_state=absent`; the list is complete for the frozen runtime configuration and maximum frame/PART count; extra, duplicate, symlink, hard-link, or unresolved grammar matches reject. `pre_run_tree` includes sorted raw-name/inode inventory hashes for the entire output root and every allowed parent. Root-external aliases are excluded by the fresh private tmpfs instance, one mount in a private non-shared namespace, no bind/clone/move, and a complete host-visible mount/FD-holder census; a hard link has no permitted creation syscall. If that invariant cannot be demonstrated, absence proof is not accepted.

For brokered `write/pwrite64`, the monitor validates the request ID, stops every sibling writer TID, copies exactly `min(requested_count,profile_limit)` or the complete bounded payload specified by the operation profile from the blocked target, and hashes those copied bytes. The broker uses the temporary same-open-file-description FD from `pidfd_getfd`, performs the corresponding `write`/`pwrite64`, records actual return count, offsets, and pre/post size, closes the duplicate, then returns exactly the performed result to the target. The complete copied content is required for every accepted output write; diagnostic-prefix-only V9 samples are insufficient for a brokered write. The kernel writer PID is the registered broker PID, not the target. Partial/error returns, signal interruption, target exit, failed response, or broker/target count mismatch leaves the attempt incomplete. The target's logical C++ emission sequence and buffer bytes are linked to the broker's actual write syscall bytes; the 64-byte BI4 header check remains limited to those header bytes.

Revise `output_file_lifecycle` cross-links: each `create_authorizations` row adds `{writer_open_request_sequence,broker_open_sequence,broker_pid,broker_pid_start_ticks,broker_transaction_id,broker_effective_flags}`; the original target request may contain `O_TRUNC`, but `broker_effective_flags` for creation must use `O_CREAT|O_EXCL` and must never contain `O_TRUNC`. Each `append_session` adds `broker_open_sequences` and the unique first-creation request/broker sequence pair. Each `append_writes` row adds `{writer_request_sequence,broker_syscall_sequence,broker_transaction_id,broker_pid,broker_pid_start_ticks,payload_sha256,payload_bytes,open_file_description_id}`. Broker and target request rows are one-to-one; payload bytes/hash equal the copied target buffer; the broker syscall's kernel return/offset/size changes exactly equal the synthetic target response. The existing V10 EOF-only append invariants still apply. These relations are hashed into the signed output evidence and cannot be caller-asserted without the trusted broker transcript.

The raw fanotify ABI remains a literal record of the kernel event actor. For a content write, `event_pid/pidfd_resolved_pid/pid_start_ticks` identify the broker and `syscall_sequences` references the actual broker syscall sequence. For a target `close`, those fields identify the writer and the event references its actual close sequence. Extend each `fanotify_syscall_closure` row to exact `{writer_request_sequence,broker_transaction_id,kernel_actor_role,kernel_actor_pid,kernel_actor_start_ticks,kernel_syscall_sequences,permission_event_refs,notification_drain_id,notification_event_refs,notification_disposition}`. `kernel_actor_role` is `writer` or `broker`, determined from pidfd/start-time identity. Each raw event maps to exactly one actual kernel syscall; broker events additionally map to exactly one target request through the signed broker transcript. A notification event generated by a broker operation is never falsely attributed to the target PID. The serialized broker transaction and drain protocol remain mandatory; any event/syscall actor mismatch or missing request↔broker↔event edge leaves evidence missing/open.

## 2. Separate file-backed ELF objects from kernel virtual mappings

Replace V9's equality between all initial executable mappings and file-backed `initial_image_objects`. The Linux vDSO is automatically mapped into user processes, is an ELF image supplied by the kernel, and normally appears as `[vdso]` in `/proc/<pid>/maps`; it is not a regular file that can satisfy V9's held-file identity rule. Extend `runtime_guard` with exact `initial_virtual_mappings` alongside `initial_image_objects` and revise `initial_image_capture` so its complete parsed map set partitions into file-backed ELF mappings, kernel virtual mappings, and data-only mappings. File-backed executable ranges equal the executable ranges in `initial_image_objects`; kernel-supplied ranges equal `initial_virtual_mappings`; the disjoint union equals every executable mapping in the raw maps snapshot. No anonymous executable, mutable, writable-executable, or unclassified mapping is accepted.

`initial_virtual_mappings` has exact keys `{schema,kernel_build_id,boot_profile_sha256,records_sha256,record_count,records}`. Rows are sorted by `(mapping_kind,start,end)` and exact `{mapping_kind,label,start,end,prot_bits,object_sha256,build_id,raw_bytes_sha256,auxv_tag,kernel_source_id}`. Supported kinds are `vdso_elf`, `kernel_vvar_data`, `kernel_vvar_clock_data`, and `kernel_emulated_vsyscall`; any other mapping kind is missing/open. Ranges/protection bits exactly match held `/proc/<pid>/maps`, and `mapping_kind` is independently cross-checked against `AT_SYSINFO_EHDR`, architecture ABI, pinned kernel build, and boot profile. For `vdso_elf`, the verifier reads the complete bounded in-memory ELF image while the child is stopped, validates ELF headers/program headers/versioned symbols, and hashes the exact captured bytes; `object_sha256` and `raw_bytes_sha256` bind that image. It is added to the loader/disassembly profile as `object_kind=kernel_vdso`; a build ID is required when present in its ELF notes, and a missing debug file is allowed only for this vDSO object when raw instruction decoding, symbol/version tables, direct/indirect target closure, and executable-byte coverage are complete with zero unresolved targets. No path-like file identity is fabricated. `kernel_vvar_data`/`kernel_vvar_clock_data` are non-executable kernel-provided inputs; their bytes may change during runtime and are not claimed to be immutable. Their range, permissions, kernel build, ABI role, and permitted vDSO readers are pinned instead. `kernel_emulated_vsyscall`, when present on the pinned architecture, binds the exact raw maps entry, fixed entry range, boot `vsyscall` mode, kernel build, and allowed emulated entrypoints; if its behavior or source cannot be pinned, the host is unsupported. See [vdso(7)](https://man7.org/linux/man-pages/man7/vdso.7.html) and the [Linux proc maps documentation](https://docs.kernel.org/filesystems/proc.html).

Extend `loader_disassembly_profile.objects` exact rows with `object_kind` (`file_elf` or `kernel_vdso`), `mapping_source` (`held_regular_file` or `stopped_process_memory`), and `build_id_source` (`elf_note`, `kernel_build_profile`, or `absent_vdso_note`). `object_sha256` for file ELF remains the held-file hash; for vDSO it is the exact captured ELF-image hash. The loader's complete object/call/indirect-target closure includes the vDSO as a user-executable object, while the vvar and vsyscall emulator remain in the separately typed kernel virtual mapping profile. At the `_dl_init` stop, all ranges, bytes, auxv address, map rows, kernel build ID and profile hash must agree. Any missing vDSO read, unrecognized virtual map, changed map, anonymous executable region, or unresolved vDSO target makes the attempt missing/open.

## 3. Scope and authority

V11 is a design amendment only. It does not deploy the broker, query host capabilities, test `pidfd_getfd`/fanotify/seccomp support, run a binary, read production inputs, start GenCase/native/solver/worker/GPU/queue, connect evidence to a gate, or change registry/ledger/denominator/qualification credit. Independent read-only review is required. Host capability probes and every actual execution remain outside this static-review authorization.
