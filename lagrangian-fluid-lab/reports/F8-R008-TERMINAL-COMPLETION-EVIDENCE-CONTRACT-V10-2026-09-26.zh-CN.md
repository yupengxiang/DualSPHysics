# F8 R008 Terminal Completion Evidence Contract v10

**Status:** additive proposal only; diagnostic-only; no solver/execution/readiness/qualification authority. Effective contract remains v3 plus v4–v9 and this amendment. V1–V9 and review records remain immutable. The trust service, Linux supervisor, syscall/fanotify monitors, and verifier are not deployed.

V9 review result: `REVISE`, no P0. The review did not attest reviewer model identity. V10 addresses the two output-open semantics found against the current CPU writer, the missing eager-binding condition, the non-algorithmic fanotify correlation clause, the unfrozen cgroup-v2 mode, and `FAN_ONDIR` terminology. No restart, horizon, terminal-save, trust, zero-credit, or authorization rule changes.

## 1. Fresh output creation and explicitly bounded append-only files

Replace V9's blanket output-FD `O_APPEND|O_TRUNC` and `lseek` prohibitions only as specified in this section. All other output paths retain the V9 denial policy.

The source-derived CPU writer profile must include, at minimum, these call chains: `JPartDataBi4::SaveFileData()` → `JBinaryData::SaveFile()` (`src/source/JPartDataBi4.cpp`, `src/source/JBinaryData.cpp`); `JPartDataHead::SaveFile()` → `JBinaryData::SaveFile()` (`src/source/JPartDataHead.cpp`, `src/source/JBinaryData.cpp`); `JSph::SaveRunPartsCsv()` → `JSaveCsv2::OpenFile()` (`src/source/JSph.cpp`, `src/source/JSaveCsv2.cpp`); and `JPartDataBi4::SaveFileInfo()` → `JBinaryData::SaveFileListApp()` (`src/source/JPartDataBi4.cpp`, `src/source/JBinaryData.cpp`). The current source opens fresh BI4 files with `fstream::open(..., ios::binary|ios::out)`. RunPARTs and PartInfo append on later PARTs when their pathname already exists; both call `seekp(0,end)`, and the append paths use `ios::app`. The frozen callgraph/source hashes must cover these functions and the exact C++ runtime/libstdc++ build that maps the stream modes to syscalls. A changed source/runtime needs a new profile.

Add exact signed `output_file_lifecycle_profile` keys `{schema,profile_id,profile_sha256,fresh_create_paths,append_only_paths,unprofiled_path_policy}`. Its hash omits only `profile_sha256`. Both path arrays are sorted by `(root_role,path_rule_id)` and contain exact rows `{path_rule_id,root_role,path_grammar,source_emission_id,first_open_policy,max_matches}`. `root_role` is `data_output` or `run_output`; `path_grammar` is a versioned, finite path grammar rooted at the held output-root FD (not a glob); `first_open_policy` is exactly `create_if_absent_with_truncate`; `max_matches` is a positive bounded count. `append_only_paths` contains only source-closed append outputs, initially `RunPARTs.csv` and `PartInfo.ibi4`, with their exact directory root, producer callsite IDs, allowed PART-index cardinality, and maximum byte count. No path may be in both arrays. Any path outside these grammars is denied. The complete source inventory must also account for logs and optional outputs selected by the frozen runtime configuration; until that inventory is closed, the profile is incomplete/open.

Add exact `output_file_lifecycle` evidence keys `{schema,profile_sha256,pre_run_tree,create_authorizations,append_sessions,append_writes,record_count,records_sha256}`. `pre_run_tree` is an exact, sorted held-root-FD census of `{root_role,path_bytes_base64,dev,ino,mount_id,mode,nlink,size_bytes}` rows, bound to root identities and raw names; it proves each governed leaf was absent before writer admission and that no unregistered hard-link/path alias existed. `create_authorizations` is a sequence-sorted array with exactly one row per allowed fresh creation. Each row is exactly `{sequence,syscall_sequence,writer_pid,writer_pid_start_ticks,writer_tid,writer_tid_start_ticks,parent_dev,parent_ino,parent_mount_id,parent_fd_token,basename_base64,basename_sha256,lookup_errno,lookup_monotonic_ns,open_flags,requested_mode,open_result_fd,file_description_id,dev,ino,mount_id,result_st_mode,nlink,size_after_open,path_rule_id}`. IDs are positive and unique; basename is one nonempty path component with no slash or NUL; `lookup_errno=ENOENT`; `open_flags` contains `O_CREAT|O_TRUNC`, excludes `O_APPEND`, and matches the signed access/mode policy; `requested_mode` is the exact syscall mode argument and `result_st_mode` is the exact post-open `st_mode`. The lookup is performed by the trusted monitor through a held parent directory FD immediately before the traced open. The open must return the same resolved parent/name, a regular single-link file on the pinned output mount, and `size_after_open=0`. The target task and all sibling writer TIDs remain stopped between absence proof and the open; the private mount has no external writable holder; no supervisor/monitor mutation is permitted in that interval. The resulting dev/inode/file-description identity is registered before any writer TID resumes. A path can receive exactly one such authorization during an attempt; a second truncate-capable open, an existing leaf, or an unlisted path is denied. This is a proof of creation without destruction of prior content, not general permission to truncate.

An append session is exact `{session_id,path_rule_id,dev,ino,mount_id,first_create_syscall_sequence,first_open_close_syscall_sequence,open_syscall_sequences,initial_size,final_size,write_count,write_sequences_sha256}`. It binds one inode per allowlisted path rule; that inode is created during this attempt under the fresh-absent rule, and every later open resolves to the same inode and uses `O_APPEND`, with no `O_TRUNC`; the permitted access mode is exactly the mode in the source profile. `first_create_syscall_sequence` is a positive sequence in `create_authorizations`; `first_open_close_syscall_sequence` resolves to the close of that initial open-file description; `open_syscall_sequences` is sorted, unique, nonempty, and includes that first open. No unlink, rename-away, hard link, alternate writable mapping, or unprofiled write is permitted during the session. For these append-only inodes alone, `lseek(fd,0,SEEK_END)` with offset zero is allowed as a non-content operation; its returned offset must equal a monitor-sampled `st_size` for the same held inode. The initial create/open description may omit `O_APPEND` only until it is closed: its writes must be sequential, the recorded current offset must equal the pre-write `st_size`, and each successful return advances size and offset by exactly the returned count. Every later open and write must carry `O_APPEND`, so each successful write extends the current EOF. `append_writes` is sorted by syscall sequence and binds each successful `write` record to `{session_id,syscall_sequence,size_before,size_after,return_count}`; `size_after=size_before+return_count`, and the next write's `size_before` equals the previous `size_after`. A zero/partial write is handled by its actual return count; any gap, overwrite, size regression, unobserved write, or identity change rejects. The final size and inode must match the sealed output tree. `pwrite64`, vectored/copy/async writes, `ftruncate`, writable mappings, and content-mutating ioctls remain forbidden for append-only files. `record_count` equals the total lifecycle rows; `records_sha256` hashes the canonical `{create_authorizations,append_sessions,append_writes}` object; evidence byte/row caps inherit V9 limits. All FD, inode, sequence, nullability, and integer widths use V9's ABI bounds; nullable fields are allowed only where a path is not output-scoped, and then the closure row's nullability rule applies.

For fresh-only output files, only sequential `write` and positioned `pwrite64` to their registered regular-file FDs remain permitted. `O_APPEND` and `lseek` remain denied. The V9 first-64-byte write sample remains diagnostic only; BI4 logical-header bytes and final sealed hashes keep their existing, narrow claims. A permitted `O_TRUNC` is never accepted on a pre-existing leaf, even if it currently has length zero.

## 2. Mechanically closed fanotify/syscall correlation

Replace V9's “complete compatible syscall set uniquely derivable” clause. The signed output evidence adds exact `fanotify_syscall_closure` keys `{schema,record_count,records_sha256,records}` and `notification_drain_records` keys `{schema,record_count,records_sha256,records}`. There is exactly one closure row for every writer `syscall_records` sequence, including calls that cannot affect the output filesystem. Closure rows are exactly `{syscall_sequence,writer_pid,writer_pid_start_ticks,writer_tid,writer_tid_start_ticks,operation_class,output_object_ref,expected_permission_profile_id,permission_event_refs,notification_drain_id,notification_event_refs,notification_disposition}`. All event references are `{group_id,sequence}`. Rows are ordered by `syscall_sequence`; each record's writer identity equals its syscall row; `output_object_ref` is independently derived from the syscall FD/path identity and held mount/root descriptors, not caller text. `output_object_ref` is null exactly for `not_output_scoped`; `expected_permission_profile_id` is null exactly when the syscall/path cannot generate a permission event under the pinned profile; event-ref arrays are sorted unique and empty iff the corresponding event class has no event. `notification_drain_id` is null exactly for `not_output_scoped`, and otherwise resolves to the unique drain row for this syscall, including failed output-scoped calls.

The trusted monitor enforces a global output-syscall gate for every writer TID before the first writer instruction can execute. The pinned seccomp profile routes every syscall that could address or mutate the output mount through `SECCOMP_RET_USER_NOTIF`; unknown and forbidden output operations are denied. The supervisor copies every policy-relevant pointed-to pathname/structure from the blocked task before making a decision, checks the notification ID is still valid, and uses the pinned ptrace syscall-exit stop to observe the actual kernel result. Only one output-capable syscall notification is released to the kernel at a time; all sibling writer TIDs remain blocked at the gate until that syscall exits and its name-group drain reaches EAGAIN. New TIDs inherit the filter and are enrolled before their first user instruction. If any path/FD operation can bypass the gate, if the monitor cannot prove no output syscall is in flight, or if notification memory can change after the supervisor copies it, the attempt is missing/open. This prevents an already-running sibling syscall from racing the nominal syscall-entry stop. A `FAN_*_PERM` event is associated only with the unique active syscall that is blocked awaiting that permission response; its event is never merged with another permission event, and its response write must match that syscall. The immutable monitor protocol, not a claimed timestamp window, establishes this per-syscall interval. The seccomp user-notification and tracee-memory rules follow the [Linux seccomp filter documentation](https://docs.kernel.org/userspace-api/seccomp_filter.html).

Add exact signed `writer_syscall_gate` keys `{schema,monitor_sha256,seccomp_profile_sha256,listener_token,intercepted_syscall_nrs,record_count,records_sha256,lost_records,records}`. `intercepted_syscall_nrs` is the sorted unique set of all ABI syscall numbers whose pinned argument/FD/path rules can address the output mount; it is mechanically derived from the closed syscall ABI profile, and every other unknown/unprofiled syscall is denied. Gate rows are exactly `{sequence,notification_id,pid,pid_start_ticks,tid,tid_start_ticks,audit_arch,syscall_nr,entry_args_sha256,decision,syscall_sequence,exit_sequence,drain_id,response_code}` and sorted by sequence. `decision` is `continue_one` or `deny_errno`; each `continue_one` row has exactly one matching syscall row and, if output-scoped, one matching closure/drain row before the next gate notification is continued. Per-TID filter installation/inheritance is recorded before the first user instruction; all task identities are start-time bound. Notification IDs are validated immediately before response, sequences are contiguous, `lost_records=0`, and all row/hash/byte limits inherit V9. No tracee or sibling may mutate policy-relevant memory between copying arguments and kernel execution; process-memory writers/ptracers outside the registered supervisor are excluded by the signed isolation profile. A missing gate row, unmatched syscall, unexpected response, or second continued output syscall before the first syscall's exit+drain rejects.

Each drain row is exactly `{drain_id,trigger_syscall_sequence,group_id,writer_tasks_stopped,read_sequence_start,read_sequence_end,event_refs,eagain_observed,eagain_monotonic_ns,overflow_count}`. `group_id=name_group`; read-sequence bounds are positive monitor-local sequence cursors, and an empty drain has equal start/end cursors and an empty `event_refs`. For a name-group drain, `trigger_syscall_sequence` is the just-completed syscall, `writer_tasks_stopped=true`, `eagain_observed=true`, all events read since the prior boundary are assigned to this drain, and no event can belong to two drains. Its EAGAIN timestamp is after the syscall-exit timestamp and before any writer TID resumes. A permission event is instead assigned while the unique triggering syscall is blocked; it has no name-group drain. The pre-coverage queue is drained and required empty before `coverage_start_ns`. Both event groups have zero loss/overflow. Closure/drain arrays are bounded to V9's syscall/event caps; hashes are SHA-256 over the versioned canonical ordered arrays.

`notification_disposition` is one of `not_output_scoped`, `failed_before_filesystem_access`, `events_drained`, or `zero_events_by_pinned_kernel_profile`. The last value is legal only where the signed kernel/filesystem/syscall semantics profile specifies an exact zero-event outcome for that operation class, return value, object type, and path state. For other output-scoped successful calls, the exact expected event mask/cardinality comes from that pinned semantics profile; observed references must match it exactly. Any event without one triggering syscall, any syscall without one closure row, any missing expected event, any event beyond the recorded EAGAIN boundary, or any ambiguity leaves the attempt missing/open. Each name-group raw event's `syscall_sequences` is exactly the singleton `[trigger_syscall_sequence]`; each permission event references exactly its one active syscall. A single syscall may reference events in both independent groups, but no event may be attributed to multiple syscalls.

The monitor's stop/drain protocol is mandatory because Linux may merge consecutive same-object/same-origin notification events, while permission events are not merged. The protocol drains between writer syscalls so cross-syscall merging cannot erase attribution. The pinned preflight must verify that the target kernel/filesystem emits the exact per-syscall event set used by the semantics profile; unsupported or non-repeatable behavior is missing/open. No one-event-per-write assertion is made where the kernel profile specifies a combined event mask for one syscall. See [fanotify(7)](https://man7.org/linux/man-pages/man7/fanotify.7.html).

## 3. Eager symbol binding before the guarded phase

V9's post-capture prohibition on `symbol_resolution` remains, and this section adds an admission prerequisite rather than allowing lazy resolution after capture. Extend `loader_disassembly_profile` with a hash-bound `binding_profile` containing exact keys `{schema,mode,environment_policy,objects,unresolved_lazy_relocation_count,unresolved_plt_slot_count,profile_sha256}`; its canonical hash omits only `profile_sha256`. `mode` is exactly `eager_all_initial_objects`; `environment_policy` pins the nonempty exact value `LD_BIND_NOW=1` and the complete sanitized loader environment. Every object row is exactly `{object_sha256,build_id,dynamic_flags,bind_now_tag,eager_binding_source,plt_relocation_count,ifunc_relocation_count,unresolved_lazy_relocation_count,unresolved_plt_slot_count}` and is sorted by `object_sha256`. `dynamic_flags` contains the exact nullable `DT_FLAGS` and `DT_FLAGS_1` words; `bind_now_tag` is `DF_BIND_NOW`, `DF_1_NOW`, `both`, or `none`; `eager_binding_source` is `object_tags`, `LD_BIND_NOW`, or `object_tags_and_LD_BIND_NOW`.

The pinned dynamic linker must observe the exact `LD_BIND_NOW=1` environment at startup; per-object NOW tags are recorded as additional evidence. For an object lacking a NOW tag, the pinned linker profile must establish that `LD_BIND_NOW` applies to that object; the observed relocation inventory at `_dl_init` must independently show eager completion. At the `_dl_init` stop, each object's unresolved-lazy and unresolved-PLT-slot counts are exactly zero, and all PLT/GOT targets resolve to the pinned initial closure. `unresolved_lazy_relocation_count` and `unresolved_plt_slot_count` are zero both per object and in aggregate. Missing environment evidence, unsupported loader semantics, an unresolved IFUNC/PLT target, a post-capture lazy bind, or an object whose eager-binding state cannot be derived leaves the attempt missing/open. No lazy resolution after capture is allowed. `LD_BIND_NOW` is documented to force startup symbol resolution; NOW tags and the observed zero-unresolved runtime inventory are retained as independently checkable evidence rather than substituting one for another. See [ld.so(8)](https://man7.org/linux/man-pages/man8/ld.so.8.html), [GNU libc Dynamic Linker Hardening](https://sourceware.org/glibc/manual/2.43/html_node/Dynamic-Linker-Hardening.html), and [GNU libc Indirect Functions](https://www.sourceware.org/glibc/manual/latest/html_node/Indirect-Functions.html).

## 4. Pin cgroup v2 domain semantics and stable census points

Replace V9's cgroup type assumptions with an exact `cgroup_profile` key set `{schema,cgroup2_superblock,version,cgroup_type,leaf,no_threaded_descendants,placement_policy,migration_policy,freeze_policy,mount_id,device,inode}`. This task accepts only a cgroup-v2 filesystem (`CGROUP2_SUPER_MAGIC`), `version=2`, a leaf `cgroup.type` whose exact raw value is `domain\n`, no child cgroups, and a single held cgroup directory FD. Placement is only by the supervisor's frozen launch method before writer execution; writer and unregistered roles cannot write `cgroup.procs`, `cgroup.threads`, `cgroup.type`, or `cgroup.freeze`. Thread migration after admission is denied. A `threaded`, `domain threaded`, hybrid, v1, nested, unreadable, or differently mounted configuration is missing/open.

Add exact raw `cgroup_type_before` and `cgroup_type_after` records using the V9 `{raw_base64,raw_sha256}` schema, and bind them to the same held cgroup directory identity as the six existing `cgroup.procs`, `cgroup.threads`, and `cgroup.events` snapshots. Add bounded, ordered `cgroup_freeze_transitions` rows exactly `{sequence,write_raw_base64,write_sha256,readback_events_ref,monotonic_ns}`; each write is exactly one of the byte strings `0`, `1`, `0\n`, or `1\n`, and each reference resolves to a held-FD `cgroup.events` snapshot. Before taking `task_snapshot_before` and the before ID sets, the supervisor writes freeze=1 and waits until the kernel's `cgroup.events` reports `frozen 1`; all sets and per-task records are collected while that state remains true. Freeze alone is not treated as a migration barrier: the signed cgroup delegation/permission profile and host supervisor policy must prove that no other actor can write `cgroup.procs`, `cgroup.threads`, `cgroup.type`, create/remove children, or move a task during census; such an actor or an unclosed migration path leaves evidence missing/open. After teardown, both ID sets must be empty, `cgroup.events` must report `populated 0`, and `cgroup.type` must still be exactly `domain\n`. The before/after process-leader and TID relation is asserted only for this pinned cgroup-v2 domain-leaf mode: sorted `cgroup.procs` equals the unique PID projection of sorted `cgroup.threads`. All six source snapshots, the two type snapshots, mount/superblock identity, freeze transitions, and syscall sequence references are jointly bound in the signed evidence. The kernel documents that freezing is asynchronous and that frozen tasks may still enter or leave a cgroup, so both the `frozen 1` readback and closed migration authority are mandatory ([Control Group v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)).

## 5. FAN_ONDIR is an event-mask bit, not a mark flag

Replace V9's phrase “`FAN_ONDIR` mark modifier.” `FAN_ONDIR` is included as a bit in the `fanotify_mark()` event mask alongside the selected event types, and may be returned in an event mask as the directory modifier. It is not supplied in `fanotify_mark()`'s `flags` argument. Preserve V9's rule that it is not an event type, is separated from returned event-type bits during parsing, and may appear only when the pinned event object is a directory. An implementation that places it in mark flags is incompatible and must fail preflight. See [fanotify(7)](https://man7.org/linux/man-pages/man7/fanotify.7.html) and [fanotify_mark(2)](https://man7.org/linux/man-pages/man2/fanotify_mark.2.html).
