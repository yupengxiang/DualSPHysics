# F8 R008 Terminal Completion Evidence Contract v12

**Status:** additive proposal only; diagnostic-only; no solver/execution/readiness/qualification authority. Effective contract remains v3 plus v4–v11 and this amendment. V1–V11 and review records remain immutable. No trusted I/O broker, Linux supervisor, syscall/fanotify monitor, or verifier is deployed.

V11 review result: `REVISE`, no P0. The configured Terra High review identified four P1 closure gaps and one P2 map-schema gap. This amendment makes descriptor injection exact, freezes every shared target address space during broker copy-in, separates broker and fanotify-responder roles, defines a mechanically closed syscall disposition table, and makes mutable kernel maps hash-conditional. A source cross-check also found that emulating `read`/`fstat` would require writing kernel-shaped output bytes into the target's address space; V12 instead leaves a narrow, FD-bound read-only allowlist to the kernel and brokers only content writes and pathname operations. Reviewer model identity was not attested.

## 1. Exact target-FD injection and table stability

Replace V11 §1's unspecified target-FD allocation with this rule. Every successful `SECCOMP_IOCTL_NOTIF_ADDFD` uses both `SECCOMP_ADDFD_FLAG_SETFD` and `SECCOMP_ADDFD_FLAG_SEND`. `newfd` is an explicit number in the signed reservation policy; the returned syscall value equals that number. The profile records `{notification_id,broker_transaction_id,newfd,newfd_flags,adfd_flags,target_files_table_id,prior_slot_state,fd_table_census_id}`. `prior_slot_state` must prove the slot is vacant immediately before the atomic ADDFD operation. Because `SETFD` atomically replaces an occupied target descriptor, a merely in-range number is never sufficient.

Before injection, the supervisor freezes and inventories every task sharing the target `files_struct`, records all open FD numbers and identities, and proves the chosen slot vacant. The census remains stable until ADDFD commits. It also pins `RLIMIT_NOFILE`, `nr_open`, target-FD flags, and every inherited descriptor. Any unregistered task sharing the file table, FD-table mutation race, occupied slot, or identity mismatch rejects the transaction. Between transactions, the signed syscall policy mediates or denies every FD-creating, duplicating, replacing, passing, bulk-closing, or exec operation; no operation may allocate into the reserved output range except the matching broker transaction. This includes the pinned ABI's `open*`, `dup*`, `fcntl` duplication, `close_range`, `SCM_RIGHTS` receive, and other descriptor-producing calls. Target `close` of a registered output FD is separately recorded and cannot make a later allocation silently reuse the number.

## 2. Address-space stability and syscall output policy

Replace V11's “sibling writer TIDs” condition. Before copying any pathname, `open_how`, write payload, or other target-supplied memory, the supervisor establishes a stable census of all live tasks sharing the target `mm_struct`. The notified TID remains blocked in its notification; every other task sharing that address space is stopped and held through argument capture, broker dispatch, result commit, and transaction record finalization. The census binds each TID to start time and the same `mm` identity. Thread/process creation, `CLONE_VM`/`vfork`, external process-memory writes, ptracing, signal handlers, and mapping changes are denied or independently excluded for the entire interval. If complete `mm`-sharing census or stop coverage cannot be proved, the attempt is incomplete/open. A thread count alone is not proof.

The broker does not emulate output-FD `read`, `pread64`, or `fstat`, which require copying result bytes/structures into target memory. The signed seccomp profile may statically `ALLOW` only these non-content-mutating operations on an already registered output FD, plus `fcntl(F_GETFL/F_GETFD)` and `close`. Their actual kernel syscall records, results, FD identity, and any applicable fanotify permission events remain mandatory evidence. No pathname-based variant receives this exception. `lseek` remains broker-emulated through the temporary same-open-file-description FD and returns only its scalar result. `fcntl(F_SETFL)`, duplication, descriptor passing, and all other `fcntl` commands are denied unless separately and exactly broker-emulated. The source-profiled append FDs carry immutable `O_APPEND`; a read may change their shared offset but cannot redirect a later append write away from EOF. `O_APPEND` cannot be cleared or replaced during the attempt. All content-mutating output syscalls, output-path operations, and any call outside this explicit nonmutating allowlist are broker-emulated or denied; none uses `SECCOMP_USER_NOTIF_FLAG_CONTINUE`.

For brokered `write`/`pwrite64`, the complete requested payload must be copied from the frozen target address space. If `requested_count` exceeds the signed per-operation byte cap, deny before any filesystem side effect; never copy a prefix and then perform a larger write. Otherwise hash the entire copied payload and bind it to the exact broker syscall. Partial kernel writes are returned as partial results and make terminal evidence incomplete unless the source-level call and subsequent retries are fully accounted for. The target receives only scalar syscall results from broker emulation; no broker operation may claim successful user-buffer copy-out. The pinned ABI table classifies every call needing pointer input/output as brokered, kernel-native read-only, or denied, with exact bounds and error semantics.

Add exact `output_syscall_policy` rows `{audit_arch,syscall_nr,syscall_name,fd_arg_indices,path_arg_indices,fd_effect,filesystem_effect,disposition,record_source,exception_id}`. The signed table is expanded from the frozen ABI and source/runtime profile; it is sorted, unique, complete for every syscall that can reach the output mount or affect output-FD provenance, and cross-checked against the V9 `syscall_abi_profile`. Dispositions are exactly `broker_emulated`, `deny_errno`, or `static_allow`. At minimum it explicitly classifies `open/openat/openat2/creat`, all `read/write/pread/pwrite` and vectored variants, `lseek`, `fcntl`, `dup/dup2/dup3`, `close/close_range`, `sendmsg/recvmsg` descriptor passing, `execve*`, `fork/clone/clone3/vfork`, `io_uring_setup/enter/register`, `sendfile`, `copy_file_range`, `splice/vmsplice`, `truncate/ftruncate/fallocate`, output-backed `mmap/mprotect/pkey_mprotect/msync/madvise`, `ioctl`, `open_by_handle_at`, path rename/link/unlink/create operations, and metadata/xattr mutation. Every operation is either exactly emulated, denied, or proven by argument/FD policy incapable of reaching or mutating the output object. Any absent, unknown, or newly introduced syscall is denied and makes the pinned profile stale until re-reviewed.

V11 `io_broker_profile` sets are extended with `static_allow_syscall_nrs`; the three sorted unique, disjoint sets `emulated_syscall_nrs`, `denied_syscall_nrs`, and `static_allow_syscall_nrs` exactly partition the table's output-reachable syscalls. The only `static_allow` rows are the explicit FD-bound read-only allowlist above. Every `static_allow` operation still has a complete V9 `syscall_records` row and must satisfy the matching FD/status/event cross-links. `close` is lifecycle-sensitive and must have its exact V9 syscall record and fanotify relation even though it cannot modify content; it is not treated as an unobserved operation.

## 3. Broker trace and fanotify response separation

The broker is not the fanotify permission responder. Add a separately pinned `fanotify_responder_profile` binding responder executable/runtime hashes, identity, listener/group IDs, event parser, response syscall ABI, policy hash, record bounds, and the supervisor relation. It remains live while the broker may block on permission events. For a broker `open*`, the broker syscall-entry record and transaction/path decision are committed before entering the kernel; the independent responder validates the ensuing `FAN_OPEN_PERM` event against that transaction and replies exactly once. The broker syscall-exit result and resulting FD identity then close the relation. Failure or ambiguity denies/blocks the transaction and leaves evidence incomplete; the broker cannot approve its own event.

Add exhaustive `broker_syscall_records` for the broker process, with the same entry/exit, PID/start-time, FD, path, result, and sequence closure as the writer's V9 syscall records. The frozen broker syscall ABI denies unprofiled broker filesystem activity and confines all broker path/FD access to the private output tmpfs and separately pinned immutable inputs. Each broker `open`, `write/pwrite64`, temporary `pidfd_getfd`, and FD close is mapped to applicable permission/name-group fanotify events and serialized drain records. `FAN_MODIFY` events identify the broker as actor and are drained before another broker content syscall can begin; `FAN_OPEN_PERM` is answered by the separate responder; the target's actual final `close` remains attributed to the target.

The profile must distinguish an FD close from final release of its open file description. `pidfd_getfd()` creates a duplicate referring to the same open file description and shares status flags and file offset; closing that temporary duplicate while the target still holds the description is not asserted to be a final `FAN_CLOSE_WRITE`. The pinned kernel build/source profile binds the actual fanotify close hook. A raw close event is required exactly where that kernel emits it, attributed to the task whose operation causes final release; any unexpected, missing, merged, or actor-mismatched event leaves evidence open. This closes V11's broker-actor gap without inventing a close event for each duplicate-FD release. See [pidfd_getfd(2)](https://man7.org/linux/man-pages/man2/pidfd_getfd.2.html), [fanotify(7)](https://man7.org/linux/man-pages/man7/fanotify.7.html), and the pinned Linux [`fs/file_table.c`](https://github.com/torvalds/linux/blob/master/fs/file_table.c) final-release path.

## 4. Complete initial-map partition

Replace V11 §2's incomplete map partition with exact `initial_data_mappings` alongside `initial_image_objects` and `initial_virtual_mappings`. Every raw `/proc/<pid>/maps` row at the `_dl_init` stop appears exactly once in one of these disjoint classes: file-backed ELF/image mapping, supported kernel virtual mapping, or data-only mapping. Their union equals the complete raw map snapshot, not only executable ranges. Executable ranges are fully partitioned between file-backed ELF and executable kernel-emulated mappings; no anonymous executable, writable-executable, mutable code, or unknown classification is accepted.

`initial_data_mappings` has exact keys `{schema,records_sha256,record_count,records}`; each record is `{start,end,prot_bits,label,backing_kind,dev,ino,mount_id,file_offset,source_object_sha256,classification}`. Rows are sorted by `(start,end)` and reproduce every non-executable, non-kernel row of the raw maps snapshot. `backing_kind` is `held_regular_file` or `anonymous`; `classification` is a closed, pinned enum for ELF data/relro, heap, stack, anonymous-private, or a separately named source-specific data region. For `held_regular_file`, `dev/ino/mount_id/file_offset/source_object_sha256` are non-null and bind the held object; for `anonymous`, those five fields are null and the exact range/protection/label is recorded without claiming byte immutability. Unclassified rows reject.

Make `object_sha256`, `build_id`, and `raw_bytes_sha256` conditional in `initial_virtual_mappings.records`: all three are required and bind captured bytes for `vdso_elf` (with build ID required when present); all three are null for mutable `kernel_vvar_data` and `kernel_vvar_clock_data`; and byte hashes are null for `kernel_emulated_vsyscall`, which is instead pinned by exact map range, architecture ABI, boot mode, kernel build/source, and supported entrypoints. No mutable vvar bytes are represented as immutable hashes. Every nullable condition is a schema-level branch keyed by `mapping_kind`, not caller discretion.

## 5. Scope and authority

V12 is a design amendment only. It does not deploy or test the broker/responder, query host capabilities, run a binary, read production inputs, start GenCase/native/solver/worker/GPU/queue, connect evidence to a gate, or change registry/ledger/denominator/qualification credit. Independent read-only review is required. Host capability probes and every actual execution remain outside this static-review authorization.
