# F8 R008 Terminal Completion Evidence Contract v8

**Status:** additive proposal only; diagnostic-only; no solver/execution/readiness/qualification authority. Effective contract is v3 plus v4–v7 and this amendment. V1–V7 and review records remain immutable. Required trust service, Linux supervisor, audit monitor, locale monitor, and verifier are not deployed.

V7's Terra High-config review was `REVISE`, without P0 and without independent model-identity attestation. V8 addresses its five findings. Where V8 conflicts with an earlier version, V8 controls. All inherited fresh-run, positive-horizon, in-loop terminal-save, trust, zero-credit and no-authorization rules remain unchanged.

## 1. One raw syscall trace is the path/event authority

In the exact V6 `output_seal_evidence` keys, replace `fanotify_profile` with `fanotify_profiles`; add required `syscall_profile`, `syscall_records`, `fanotify_raw_events`, and `writer_emission_events`; retain every other V6/V7 key. Every nested object/row is exact-keyed with `additionalProperties=false`. Replace V7 `termination_watch.events` rows with exact `{sequence,monotonic_ns,kind,actor_pid,actor_start_ticks,path_before,path_after,fd,mount_id,open_flags,byte_count,syscall_sequence,fanotify_sequences}`. It is a deterministic projection of these signed records, not an independently asserted pathname log: there is exactly one projection row per relevant syscall record, plus the single seal control row; each adds the syscall reference and sorted fanotify references, and hand-authored projections reject.

`syscall_profile` is exactly `{schema,monitor_sha256,audit_arch,abi_profile_id,syscall_allowlist,syscall_denylist,coverage_start_ns,coverage_stop_ns,record_count,records_sha256,lost_records,max_records}`. `syscall_allowlist` and `syscall_denylist` are sorted, disjoint, unique syscall-number arrays for the pinned ABI; every syscall that can access/change the output mount, create a process/thread, load executable code, or change a monitored descriptor is classified. Locale library calls are covered by the v6 locale ABI monitor rather than pretending they are syscalls. Unknown numbers are denied for the solver and output-root verifier. The monitor records every attempt in either class, including denied calls. `record_count` equals array length and is 1..1,000,000; `records_sha256` is SHA-256 of the canonical ordered rows; evidence bytes ≤64 MiB; sequence contiguous from 1; loss exactly zero.

Each `syscall_records` row has exactly:

~~~text
{sequence,monotonic_ns,pid,pid_start_ticks,tid,tid_start_ticks,audit_arch,
 syscall_nr,syscall_name,entry_args_base64,exit_value,errno,phase,
 fd_refs,result_fd,path_refs,effect,fanotify_sequences,io_prefix_base64}
~~~

All IDs, times, syscall numbers and errno values are exact bounded integers; raw argument bytes use the pinned ABI layout, and re-decoding must yield every decoded field. `phase` is `writer`, `seal`, or `verify`. `fd_refs` is a sorted array of exact `{arg_index,fd,dev,ino,mount_id,open_flags,position_before,position_after}` rows for every descriptor argument; `result_fd` is null or exact `{fd,dev,ino,mount_id,open_flags}` and must bind a successful descriptor-returning syscall to an independent held-FD/statx observation. `path_refs` has at most two exact rows `{arg_index,dirfd,dirfd_dev,dirfd_ino,dirfd_mount_id,path_base64,resolve_flags,path_before,path_after,pre_statx,post_statx}`. Path bytes are the exact syscall argument without terminal NUL; `path_before/path_after` are null or canonical output-root-relative paths resolved component-by-component with held descriptors and no symlinks; statx fields are null or exact `{dev_major,dev_minor,mount_id,ino,mode,nlink,size}`. `effect` is one of `none,open,read,write,create,remove,rename,attrib,mmap,exec,clone,thread,loader,locale,other`; `fanotify_sequences` is sorted and unique. Fields not applicable to a call are null/empty, never omitted. Rows are ordered by sequence and strictly increasing monotonic time.

The pinned monitor stops/freezes the entire writer cgroup at syscall exit before resolving post-state, captures raw entry/exit registers and arguments, binds the open FD and parent-directory identities, and samples post-state before unfreezing any writer task. `cgroup.freeze` and its readback are themselves recorded; all tasks must be frozen during the post-state sample. Rename has exactly two path refs in old/new argument order. The termination-watch projection is mechanically derived from successful/denied syscall effects and includes the syscall sequence and exact resolved before/after paths. A missing syscall record, unclassified FD, unresolved path, inconsistent fanotify event, or evidence overflow makes the attempt missing/open.

Replace V7's single fanotify group with two independently identified groups, both cross-linked to the authoritative syscall trace. This separation is mandatory: `FAN_CLASS_NOTIF` cannot make permission decisions, while FID/name-report mode is incompatible with `FAN_CLASS_CONTENT`; no group may combine those modes. The signed evidence has exact `fanotify_profiles={permission_group,name_group}` and one `fanotify_raw_events` stream per `watcher_id`.

`permission_group` profile has exact keys `{schema,watcher_id,monitor_sha256,kernel_release,kernel_build_id,uapi_header_sha256,abi_profile_id,mount_id,init_flags,mark_type,mark_flags,event_mask,queue_limit,start_monotonic_ns,stop_monotonic_ns,overflow_count}`. It uses `FAN_CLASS_CONTENT|FAN_REPORT_PIDFD`, no FID/name-report flags, a `FAN_MARK_MOUNT` mark with `FAN_MARK_ONLYDIR`, and exactly `FAN_OPEN_PERM|FAN_ACCESS_PERM|FAN_OPEN_EXEC_PERM`. The event-object FD is held and fstat/statx-bound to mount/device/inode, then cross-linked to one syscall record. Each permission event has exactly one PIDFD info record. The monitor records its response (`FAN_ALLOW` or `FAN_DENY`) and response syscall; it allows only operations authorized for the actor, phase, and frozen writer/verifier policy. Unsupported flag combinations reject before child exec.

`name_group` profile has exact keys `{schema,watcher_id,monitor_sha256,kernel_release,kernel_build_id,uapi_header_sha256,abi_profile_id,mount_id,fsid,init_flags,mark_type,mark_flags,event_mask,event_info_profile,event_info_profile_sha256,queue_limit,start_monotonic_ns,stop_monotonic_ns,overflow_count}`. It uses `FAN_CLASS_NOTIF|FAN_REPORT_PIDFD|FAN_REPORT_DFID_NAME_TARGET`, no permission-event bits, a `FAN_MARK_MOUNT` mark with `FAN_MARK_ONLYDIR`, and the v7 event mask with `FAN_OPEN_PERM|FAN_ACCESS_PERM|FAN_OPEN_EXEC_PERM` removed, plus `FAN_RENAME`. `event_info_profile` has exactly one sorted row `{mask,required_info_types,optional_info_types}` for each single event bit in `event_mask`, no extra bit, and its canonical SHA-256 equals `event_info_profile_sha256`. It pins the record set for every event bit: PIDFD is required for every event; create/delete/move require FID (target object)+DFID_NAME; rename requires FID (target object)+OLD_DFID_NAME+NEW_DFID_NAME; other path events require FID+DFID_NAME. No optional record can replace a required record. Target-FID uses the FID info type; it is not a separate info type.

Each raw event row is exactly `{watcher_id,sequence,monotonic_ns,raw_base64,raw_sha256,event_len,metadata_len,metadata_version,metadata_reserved,metadata_fd,mask,event_pid,pidfd_resolved_pid,pid_start_ticks,info_records,response,response_syscall_sequence}`; all scalar fields are reparsed from raw bytes, reserved/padding bytes are zero, and metadata version/length equal the pinned UAPI. For permission events, `metadata_fd` is nonnegative and response fields are required; for name-group notifications, `metadata_fd=FAN_NOFD` and response fields are null. Each info row is exactly `{info_type,length,pad,payload_base64,payload_sha256,decoded}`; `pad=0`; `decoded` is a closed discriminated object: PIDFD=`{pidfd_fd}`, FID/DFID=`{fsid_base64,handle_type,handle_bytes_base64}`, and each *_DFID_NAME adds `{name_base64}`. FSID is 8 bytes; file-handle length/bytes must fit the enclosing record; names are 1..256 raw bytes with exactly one terminal NUL and no interior NUL. Every info record is parsed from the raw stream, with no missing, duplicate, or trailing bytes. Rename requires exactly OLD_DFID_NAME, NEW_DFID_NAME and target FID; create/delete/move require target FID.

The syscall row has exact `io_prefix_base64`: for successful write/pwrite it contains the first `min(64,requested_count)` bytes captured from caller memory at syscall entry; other calls use null. The successful return count selects the bytes actually written. Concatenating bytes at contiguous file offsets from the first successful writes must reproduce the logical BI4 header in §5. DFID/name/target records corroborate identity; canonical paths come from syscall records, not pidfd alone. Missing records, unresolved actors, inconsistent cross-links, unsupported flags, overflow, or path mismatch rejects. The two-group restrictions and event grammar follow the pinned Linux UAPI; see [fanotify_init(2)](https://man7.org/linux/man-pages/man2/fanotify_init.2.html) and [fanotify(7)](https://man7.org/linux/man-pages/man7/fanotify.7.html).

Across all V8 rows, exact integers are JSON integer tokens with no exponent/fraction, bounded by their ABI type; signed return values use signed-64 bounds and explicit null only where the schema permits it. Base64 is canonical RFC 4648 with decoded-length limits; SHA-256 is 64 lowercase hex; text is strict UTF-8 and ≤4096 bytes unless a tighter bound applies; file-handle bytes are ≤128, syscall pathname bytes ≤4096, fanotify raw event ≤64 KiB, and syscall raw-argument bytes equal six ABI words. File names are 1..255 bytes excluding terminal NUL. Lists are capped at 65,536 unless §1's syscall cap applies. Process/file IDs and timestamps use V3 bounds. All arrays specify ordering, uniqueness and exact row counts; all nested rows forbid extra keys. `effect=other` is allowed only for an ABI-profile-enumerated syscall proven not to affect the watched filesystem, descriptor provenance, process tree, executable mappings, or locale; otherwise reject as unclassified. This common bound applies in addition to tighter per-field constraints.

## 2. Complete the process-group and cgroup evidence schema

Replace V7 `process_group_observations` with an exact array of rows `{phase,pid,pid_start_ticks,tid,tid_start_ticks,pgrp,session,proc_stat_base64,proc_stat_sha256,cgroup_dev,cgroup_ino,cgroup_mount_id}`. `phase` is one of `pre_exec,child_start,writer_exit,cgroup_empty,post_seal`; one row is required for the child and every observed writer task at every applicable phase. For process leaders read `/proc/<pid>/stat`; for non-leader threads read `/proc/<pid>/task/<tid>/stat`, through held proc descriptors. Raw bytes are parsed by the pinned proc profile; parsed PID/TID, pgrp, session and start ticks equal the row. `pgrp` and `session` are independently checked against task snapshots. `output_seal.process_group_id` equals the child's `pgrp` at `child_start`; `output_seal.writer_cgroup_inode` equals `cgroup_ino` from `fstat` of the same held cgroup directory descriptor in `cgroup_dir_stat`. Descriptor device/inode/mount identity matches every cgroup file read and every task row. No PID reuse, inaccessible proc row, inconsistent membership, or unsampled descendant is accepted.

## 3. Give every runtime-guard array a closed schema

Replace V8 `runtime_guard` with exact keys `{schema,loader_profile_sha256,seccomp_profile_sha256,monitor_sha256,coverage_start_ns,coverage_stop_ns,initial_image_objects,loader_entrypoints,loader_events,process_syscalls,executable_mapping_events,thread_events,lost_records}`. Hashes are lowercase SHA-256; times are positive signed-63-bit integers; each array is sequence-ordered or bytewise sorted as specified, ≤65,536 rows, with aggregate evidence still ≤64 MiB. `lost_records=0`; all rows have exact keys and unknown fields reject.

- `initial_image_objects` rows are exactly `{path,dev,ino,mount_id,size_bytes,mode,build_id,sha256,mapped_ranges}`; path is canonical absolute UTF-8, build ID is 1..64 lowercase hex or null, and mapped ranges are sorted exact `{start,end,file_offset,prot_bits}` with positive `start<end` and `prot_bits` the exact three-bit `PROT_READ|PROT_WRITE|PROT_EXEC` mask. This is the complete `/proc/<pid>/maps` executable-object set captured before application constructors; every executable mapping must bind to the frozen runtime closure.
- `loader_entrypoints` rows are exactly `{sequence,symbol,version,object_sha256,object_build_id,entry_offset,alias_class}`; sorted uniquely by object hash, symbol, version and offset. `alias_class` is one of `public_api,versioned_api,glibc_internal`. The frozen loader profile contains the explicit closed symbol/version/address list derived from the pinned loader/libc dynamic and version symbol tables; no wildcard or unexpanded alias family is allowed.
- `loader_events` rows are exactly `{sequence,monotonic_ns,pid,pid_start_ticks,tid,tid_start_ticks,entrypoint_sequence,caller_object_sha256,raw_args_base64,action,result,syscall_sequence}`. `action` is `denied`; `result` is the pinned denial result. Every address hit in the entrypoint list maps to one row. A successful post-exec load/resolution or unobserved entrypoint rejects.
- `process_syscalls` rows are exact references `{syscall_sequence,kind,clone_flags,child_pid,child_start_ticks,child_tid,child_tid_start_ticks,action}` to `syscall_records`; `kind` is `fork,vfork,clone,clone3,execve,execveat,unshare,setns`; `action` is `denied` or `thread_allowed`. A `thread_allowed` clone is the only allowed process-control event and must satisfy V7's ABI-specific `CLONE_THREAD` mask. Fork/vfork/clone3/exec/namespace-changing calls are all denied after initial exec. Every reference is one-to-one and values are independently decoded from raw syscall arguments/results.
- `executable_mapping_events` rows are exact references `{syscall_sequence,kind,requested_prot,fd,fd_dev,fd_ino,action}`; `kind` is `open_exec,memfd_create,mmap,mprotect,pkey_mprotect`; any operation that could create/introduce `PROT_EXEC` after initial image capture is denied. All executable mappings at exit equal the frozen initial-image ranges.
- `thread_events` rows are exactly `{sequence,monotonic_ns,kind,parent_pid,parent_start_ticks,parent_tid,parent_tid_start_ticks,child_tid,child_start_ticks,clone_syscall_sequence,registration_sequence,locale_probe_sequence}`; `kind` is `birth` or `exit`. Every allowed clone has one birth row; new TIDs remain stopped until both registration and locale probe records exist. Every birth has exactly one later exit or an exit-state row in the final task snapshot. Process identity and TID reuse are prohibited.

Every reference resolves to a unique syscall/watch/locale sequence. The runtime guard's complete row bounds, source ABI, initial-image sampling point, seccomp action and monitor build are pinned by hashes and signed raw records. If any instrumentation dependency or address range cannot be observed, return missing/open; do not infer absence from an empty array.

Runtime-guard scalar/null rules: object device/inode/mount/size and map addresses/offsets are exact unsigned ABI-width integers; object mode is regular-file `st_mode`; every mapped range in this array has `prot_bits & PROT_EXEC != 0`; ELF symbols/versions are printable ASCII ≤256 bytes; hashes/build IDs and paths obey the common V8 bounds. `entry_offset` is the ELF symbol virtual address relative to the object's load base, not an ASLR address. Loader `syscall_sequence` is null only when denial occurs before any kernel call; otherwise it references the exact load/open syscall. In `process_syscalls`, child identities are null on denied process creation and populated only for a successfully created thread; `clone_flags` is null for non-clone rows. In `executable_mapping_events`, `fd*` are null only for anonymous mappings and otherwise bind to a descriptor; every row is a denied executable-capable request. In `thread_events`, registration/locale-probe references are populated for births and null for exits; exit rows reference the exact final task-snapshot sequence. Every counter/sequence is positive unless the schema explicitly defines null; no enum extension is allowed.

## 4. Bind DsphConfig lookup to the source-computed `ProgramPath`

Replace V7's assertion that `ProgramPath` is the directory used to resolve the executable. In this source version, `main` passes `argv[0]` to `JAppInfo::ConfigRunPaths`; that method snapshots current working directory and computes `ProgramPath` as `GetDirParent(GetCanonicalPath(RunPath,RunCommand))`. `GetCanonicalPath` performs lexical `.`/`..` and separator normalization and does not resolve symlinks. Therefore `runtime_config_probe` binds to this exact source-computed string, not to `/proc/self/exe` and not to an assumed binary directory.

Extend V7 `runtime_config_probe` to exact keys `{schema,argv0_base64,startup_cwd_base64,canonical_run_path_base64,program_path_base64,program_dir_fd,program_dir_dev,program_dir_ino,program_dir_mount_id,probe_path,probe_operation,result,errno,statx_record,input_event_sequences,child_probe_syscall_sequences,directory_readonly_evidence_sha256,source_profile_sha256}`. The trusted launch record binds exact exec `argv[0]` bytes and startup cwd to the raw syscall/initial process image. The independently implemented, source-version-pinned lexical algorithm recomputes `canonical_run_path` and `program_path`; the result is byte-equal to the string used by `AppInfo::ConfigRunPaths` and to the held directory descriptor opened before exec. Any symlink component in this path is rejected because the C++ helper does not resolve symlinks. The `DsphConfig.xml` supervisor probe uses the exact V7 no-follow `openat2` rule. For `present`, `child_probe_syscall_sequences` contains the successful source-level `FileExists` stat call and the subsequent child open/read events for the same file identity/hash. For `absent`, it contains both failed child lookups from the pinned `FileType` path (`stat` and the `FileSize` stream-open fallback), each resolving to the same `ENOENT` path; `input_event_sequences=[]`. The ordered syscall records and exact pinned `FileType/FileSize` implementation prove the child made no successful lookup/read. Directory immutability/read-only coverage and present/absent rules otherwise remain unchanged. `source_profile_sha256` binds `main.cpp`, `JAppInfo.cpp/.h`, `JCfgRunBase.cpp`, `JDsphConfig.cpp`, and the relevant `Functions.cpp/.h` implementation. This replaces V7's unsupported claim that the directory descriptor is the executable's resolved on-disk parent.

## 5. Separate the source-level BI4 header event from kernel writes

Replace V7's `first_header_write_size` assumption with exact `producer_byteorder_observations` rows `{path,child_pid,child_start_ticks,writer_tid,writer_tid_start_ticks,executable_sha256,source_module_sha256,makefilehead_callsite_id,getbyteorder_callsite_id,getbyteorder_value,raw_probe_base64,probe_sequence,logical_header_event_sequence,logical_header_bytes_base64,logical_header_size,kernel_write_syscall_sequences,first_kernel_write_offset,first_kernel_write_bytes_prefix_base64,monitor_sha256}`.

The pinned source profile binds the actual `JBinaryData::MakeFileHead`/`fun::GetByteOrder` call and `JBinaryData::SaveFileData` header emission in the same child writer. `getbyteorder_value=0` is the source enum value `LittleEndian`; the raw native-memory probe is exactly `01 00 00 00`. `writer_emission_events` is a sequence-ordered array with exact tagged rows: `byteorder_probe={sequence,monotonic_ns,kind,pid,pid_start_ticks,tid,tid_start_ticks,callsite_id,source_module_sha256,output_path,result_enum,raw_probe_base64}` and `logical_header={sequence,monotonic_ns,kind,pid,pid_start_ticks,tid,tid_start_ticks,callsite_id,source_module_sha256,output_path,stream_fd,fd_dev,fd_ino,mount_id,buffer_base64,buffer_sha256,logical_size,associated_syscall_sequences}`. `kind` is exactly the row tag; identities/hashes obey V3/V8 bounds; output paths are canonical relative paths; base64 bytes match their stated sizes/hashes; `logical_size=64`; syscall sequence references are sorted and unique. For each BI4 path, the `producer_byteorder_observations.probe_sequence` references exactly one `byteorder_probe` row, and `logical_header_event_sequence` references exactly one later `logical_header` row from the same child/TID and path; the header callsite is `pf->write((char*)&head,sizeof(StHeadFmtBin))` and records exactly 64 source-level bytes. The bytes equal the independently parsed BI4 header and encode the observed byte order plus SI64 value. The syscall monitor captures the exact FD buffer prefix in `io_prefix_base64`; it does not assume std::fstream preserves the source-level call as one kernel write.

The C++ stream may buffer/coalesce logical writes, so the contract makes no claim that the first kernel `write(2)` is exactly 64 bytes. Instead, `kernel_write_syscall_sequences` bind the logical event's file descriptor to all kernel writes; `first_kernel_write_offset=0`. For each referenced syscall, bytes captured in `io_prefix_base64` are concatenated only up to the successful return length and checked against the contiguous file offsets; the first 64 resulting bytes equal `logical_header_bytes_base64`. A syscall-level write of less than 64 bytes is permitted only if subsequent contiguous writes complete the header before any data payload; the concatenated first 64 output bytes must equal the logical header. `first_kernel_write_bytes_prefix_base64` equals the first `min(64,total_written)` bytes of that concatenation. Every BI4 inventory path has exactly one producer row and one probe/header pair; no extra row or write-before-probe is allowed. The full `MakeFileHead`, `SaveFileData`, `SaveFile`, and `GetByteOrder` source/callsite closure hashes are pinned. This clause replaces V7's unsupported requirement that one kernel syscall have the exact header size.
