# F3 配方修订提案 — 2026-09-13

当前 `F3_CELL3_NS_visco1_native_nopen` 的名义 gate 仍为 `failed`。NP01↔NP06 的全窗空间差异超过预算；独立 CFL-half 对照和 `NoPenetration=True` 四层边界对照都没有消除该差异。这里记录候选修订，不授予生产资格，也不改写现有 gate。

## 候选 A：把生产粒距前瞻性改为 0.0075 m

现有同配方空间证据中，0.010↔0.0075 和 0.0075↔0.006 均通过 0.05 空间预算；当前报告中的最大能量差约为 0.03209 和 0.03130。这个候选不能直接把两个已通过的相邻 pair 拼成资格，必须新建 revision plan，重新绑定生产分辨率、控制域和所有门。

在正式批准后，最低需要为 0.0075 m 生产候选补齐：

1. 0.0075 m 的零驱动、半原生步长和 0.002 s 输出三个控制；
2. 0.9 与 1.1 两个端点在 0.010/0.0075/0.006 m 的六个空间单元；
3. 独立内部幅度 0.97 在 0.0075/0.006 m 的两个单元；
4. 重新发布 T1、时间、输出、空间和域 gate，并在通过后才启动八个独立开发 pilot。

NP01、NP05、NP06 是否可以作为修订矩阵的既有证据，必须在 revision plan 中逐项绑定输入、审计和 hash 后决定；当前计划明确把它们视为旧候选的证据，不能自动继承。

## 资源影响

当前账本为资格 61/72、GPU 约 8.807/64 h、CPU 保守上界约 654.03/768 core·h，剩余 11 次资格尝试。仅按当前求解器的保守前置预留估计，0.0075 案例约 20.53 core·h/次、0.006 案例约 29.33 core·h/次；上述 11 个新单元至少会超过现有 CPU 上限，且没有失败重试余量。因此在启动 revision matrix 前，需要新的 CPU 上限授权和相应的 qualification-attempt 余量；GPU 不是主要瓶颈。

## 不接受的替代

把评分改成只比较相邻分辨率、删除 NP01↔NP06、缩短 0–8.35 s 窗口，或把 `.0075 m` 仅因为 pair 通过而事后指定为生产配方，都与当前冻结计划不相容。`.006 m` 若要成为生产分辨率，还需要更细参考和一份新的前瞻性矩阵，不能把自己当作自己的细参考。

提案状态：`pending_owner_decision`。在批准新的 recipe plan 和资源后，才准备并启动新的 GPU 矩阵；开发数据、材料生产轨迹和训练仍保持 0。
